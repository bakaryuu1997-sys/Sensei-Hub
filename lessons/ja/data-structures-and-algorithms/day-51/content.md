# 重心分解（Centroid Decomposition）：木のクエリを極める 🌳

**第9フェーズ：Beyond Mastery**へようこそ。ここは、真にプロの競技プログラマー、あるいは巨大なデータスケールを扱うテクノロジー企業のシニアアーキテクトという高みを目指す人のための「ポストグラデュエーション（卒業後）」ステージです。

今日は、木構造における **重心分解（Centroid Decomposition）** について学びます。これは、木の上の **分割統治（Divide and Conquer）** テクニックであり、**$O(N^2)$** の複雑さを持つ問題を魔法のように **$O(N \log N)$** へと変換します。

---

## 🪝 THE HOOK：「数兆ノードの木における距離問題」

ソーシャルネットワークの分析システムを構築していると想像してください。各ユーザーは木の上のノードです（ネットワークグラフにサイクルがないと仮定します）。あなたは、「距離がちょうど $k$ であるユーザーのペアは何組あるか？」といった数百万件のクエリに答える必要があります。
-   **素朴な方法**: 各ノードについて、BFS/DFSを実行して他のノードを探します。これには **$O(N^2)$** かかります。$N = 100,000$ の場合、処理に数時間かかるでしょう。
-   **マスターの方法**: 重心分解を使用します。「重心」を通じて木をより小さな部分に分割します。分割するたびに、木のサイズは少なくとも半分になります。合計時間はわずか **$O(N \log N)$** —— つまり数ミリ秒で完了します。

「分割統治」の力は配列だけのものではありません。木に適用すると、**重心木（Centroid Tree）** と呼ばれる強力な階層構造が生み出されます。

---

## 🎭 ANALOGY：天秤の重心とバランス

1.  **重心 (Centroid)**: 木の形をした「モビール」（赤ん坊の寝床に吊るすおもちゃ）を想像してください。この木を一本の糸で完璧にバランスさせるには、持ち上げたときにどの枝の重さも全体の半分を超えないような点を見つける必要があります。その点が **重心** です。
2.  **分解 (Decomposition)**: 重心を見つけた後、そのノードを「切り離し」ます。元の木はいくつかの独立した部分木に分かれます。次に、それぞれの部分木の重心をさらに探し続けます。

このプロセスは、王国の「リーダー」を見つけ、その後、王国を小さな州に分割してそれぞれの「州知事」を見つけるようなものです……。この階層構造により、最下層からの情報を最上層へ極めて迅速に伝えることが可能になります。

---

## ⚙️ UNDER THE HOOD：重心発見アルゴリズム

$N$ 個のノードを持つ木において、あるノードを削除した後に残る各連結成分のサイズが $N/2$ 以下であるとき、そのノードを **重心（Centroid）** と呼びます。

### 重心木の構築手順:
1.  **サイズ計算**: DFSを実行して、各部分木（subtree）のノード数を計算します。
2.  **重心発見**: 任意のノードから開始し、最も大きな部分木を持つ子ノードへと移動します。どの単一の子ノードも `size > N/2` でなくなったとき、その現在のノードが重心です。
3.  **再帰**: 重心ノードに「削除済み」のフラグを立て（再訪問を防ぐため）、残りの連結成分に対して再帰的に重心を探します。
4.  **接続**: 親の重心と子コンポーネントの重心を接続して、**重心木（Centroid Tree）** と呼ばれる新しい木を形成します。

**重要な特徴**: 重心木の深さは、元の木がいかに「偏って（skewed）」いても、常に **$O(\log N)$** になります。

## 📊 BIG-O ANALYSIS：対数の支配

| 段階 | 計算量 | なぜ？ |
| :--- | :--- | :--- |
| **重心発見** | **$O(N)$** | 単純なDFSトラバーサル。 |
| **重心木構築** | **$O(N \log N)$** | 各ノードは分割の各レベルで考慮される（合計 $\log N$ レベル）。 |
| **クエリ** | **$O(\log N)$** | 重心木の葉から根へと移動する。 |
| **空間計算量** | **$O(N)$** | 追加の重心木構造を保存するだけでよい。 |

## 💻 LOGIC & PSEUDO-CODE：重心発見の実装

```javascript
/**
 * 木/部分木の重心を見つける
 */
let sz = new Int32Array(MAXN);
let deleted = new Uint8Array(MAXN);

// 部分木のサイズを計算
function getSize(u, p) {
    sz[u] = 1;
    for (let v of adj[u]) {
        if (v !== p && !deleted[v]) {
            sz[u] += getSize(v, u);
        }
    }
    return sz[u];
}

// すべての子の枝が N/2 以下であるノードを探す
function findCentroid(u, p, totalSize) {
    for (let v of adj[u]) {
        if (v !== p && !deleted[v] && sz[v] > totalSize / 2) {
            return findCentroid(v, u, totalSize);
        }
    }
    return u;
}

// メインの分解関数
function decompose(u, p_centroid) {
    let total = getSize(u, -1);
    let centroid = findCentroid(u, -1, total);
    
    // ここで問題のロジックを処理（例：距離の計算）
    // ... logic ...

    deleted[centroid] = 1;
    parent_in_centroid_tree[centroid] = p_centroid;

    for (let v of adj[centroid]) {
        if (!deleted[v]) {
            decompose(v, centroid);
        }
    }
}
```

## 🧠 LEETCODE STRATEGY：いつ重心分解を使うか？

重心分解はLeetCodeのタイトルに直接現れることは稀ですが、「Hard」な木の問題を解く鍵となります。

1.  **木の距離問題**: 距離条件（`dist(u, v) <= k` など）を満たすノードのペアを数える問題。
2.  **動的な木のパス・クエリ**: ノードの値を更新し、そのノードを通過するパス上の合計/最小/最大を計算する必要がある場合。
3.  **特定の色の最近傍ノード**: 木が変化する中で、性質 $X$ を持つ最も近いノードを探す問題。
4.  **競技プログラミングの文脈**: これらの問題は、Codeforces (Div 1) や TopCoder などのコンテストでよく見られます。これを理解することで、木の動的計画法（Tree DP）の問題を極めて迅速に解決できるようになります。

## 🎯 EXAM & INTERVIEW LOGIC：IPA ＆ 外資テック ハイレベル

-   **IPA 基本情報技術者 (科目B)**: 重心分解そのものが直接問われることは稀ですが、木のバランス特性についてはよく問われます。「すべての木には少なくとも1つ、最大で2つの重心がある」ことを覚えておいてください。
-   **外資テック シニア面接**: 「非常に偏った（Skewed）木におけるクエリをどのように最適化しますか？」という質問に出会うかもしれません。
    -   *回答*: 「**重心分解**を使用して、対数的な深さを持つ新しい階層構造を構築します。これにより、任意のパス・クエリを $O(N)$ ではなく $O(\log N)$ 時間で処理できるようになります。」これは満点の回答です。
-   **ソクラテス・ゲート**: なぜ重心木の深さは常に $\log N$ なのですか？
    -   *回答*: 各分解ステップにおいて、結果として得られるサブコンポーネントの最大サイズが `size/2` になるように重心を選ぶからです。数値 $N$ を連続して2で割ると、$\log_2(N)$ ステップで1に到達します。

## 💼 PROFESSIONAL CONTEXT：ネットワークインフラとデータクラスタ

-   **ネットワークルーティング**: 大規模な通信ネットワークにおいて、重要な「交通ハブ（重心）」を見つけることは、郊外から中心部へ、あるいはその逆へのデータ伝送を最適化するのに役立ちます。
-   **階層的クラスタリング**: データサイエンスにおいて、重心分解は大規模なデータセットを階層的なクラスタに分割し、最近傍探索を高速化するために使用されます。
-   **地理情報システム (GIS)**: マップをグラフ/木として管理します。重心は、人口密度（ノード）に基づいて放送局などの最適なカバーエリアを決定するのに役立ちます。

## 🛡️ RELIABILITY & BUGS：マスターへのアドバイス

1.  **スタックオーバーフロー**: 重心分解は深い再帰アルゴリズムであるため、$N = 500,000$ のようなケースではスタック制限に達する可能性があります。スタック制限を増やすか、`getSize` の計算に反復的なアプローチを検討してください。
2.  **「削除済み」フラグ**: 隣接リストのループ内では、常に `deleted[v]` フラグを確認することを忘れないでください。これを忘れると、アルゴリズムが無限ループに陥ったり、部分木の規模を誤計算したりします。
3.  **距離の事前計算**: 距離を扱う際、$dist(u, v) = depth[u] + depth[v] - 2 \times depth[LCA(u, v)]$ であることを思い出してください。ただし、重心分解では、ロジックを簡素化するために現在の重心から直接計算することがよくあります。
