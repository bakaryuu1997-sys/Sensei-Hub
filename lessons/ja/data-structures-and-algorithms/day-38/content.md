# 2-満足可能性問題 (2-SAT)：選択の科学 ⚖️

変数（TRUE または FALSE のみ）の集合があり、「もし A が真なら、B は偽でなければならない」といった一連の制約がある場合、何が起こるでしょうか？

**Day 38** へようこそ。今日は、論理学とグラフ理論の魅力的な架け橋である **2-満足可能性問題 (2-SAT)** について学びます。

## 🪝 THE HOOK：結婚式の招待客問題

あなたは、親族のルールが非常に厳しい結婚式の計画を立てています。
- ボブ叔父さん：「アリス叔母さんが来るなら、僕は行かない。」
- アリス叔母さん：「私か、いとこのクリスの少なくともどちらかは出席する。」
- クリス：「僕が行くなら、ボブ叔父さんも絶対に来る必要がある。」

全員が満足する招待客リストを見つけることはできますか？
招待客の数と制約が増えるにつれて、これを手作業で解くのは不可能になります。**2-SAT** は、解が存在するかどうかを判断し、存在する場合はそれを見つけ出すための数学的なエンジンです。

---

## 🎭 ANALOGY：ドミノ倒しの連鎖

それぞれの選択をドミノの一枚と考えてみましょう：
1. 変数 `A` を TRUE に倒すと、それが別のドミノを倒すかもしれません（`B` を FALSE に強制する）。
2. そのドミノがさらに別のドミノを倒し、連鎖していきます。
3. 問題はこうなります：「ある初期設定をしたとき、どのドミノも自分自身の『反対側』を倒す（例：`A` が `not A` を倒す）ことがないような構成は存在するか？」

もしそのような矛盾（自己矛盾）が見つかった場合、そのシステムは **「充足不可能 (Unsatisfiable)」** です。

---

## ⚙️ UNDER THE HOOD：論理から充足グラフへ

2-SAT のすべての制約は `(X or Y)` という形式で記述されます。
論理学において、`(X or Y)` は以下の 2 つの「含意（Implication）」と同等です：
1. もし `not X` が真なら、`Y` は真でなければならない (`!X -> Y`)
2. もし `not Y` が真なら、`X` は真でなければならない (`!Y -> X`)

### アルゴリズムの手順：
1. **含意グラフ (Implication Graph) の構築**：
   - 各変数 `Xi` に対して、2 つのノード `Xi` と `!Xi` を作成します。
   - 各制約 `(A or B)` に対して、エッジ `!A -> B` と `!B -> A` を追加します。
2. **強連結成分 (SCC) の抽出**：
   - Tarjan または Kosaraju のアルゴリズムを使用します。
3. **矛盾のチェック**：
   - 任意の変数 `i` について、`Xi` と `!Xi` が **同じ SCC** に属している場合、`Xi -> !Xi` かつ `!Xi -> Xi` であることを意味します。これは論理的に不可能です。したがって、問題は **「充足不可能 (UNSATISFIABLE)」** です。
4. **解の構築**：
   - 充足可能な場合、SCC のトポロジカル順序に基づいて値を割り当てます（Tarjan の `scc_id` は実際にはトポロジカル順序の逆順を与えます）。
   - 実装によりますが、一般に `id(Xi) < id(!Xi)` なら `Xi` を TRUE とします。

---

## 📊 BIG-O ANALYSIS：思考の速度

| フェーズ | 計算量 | 理由 |
| :--- | :--- | :--- |
| **グラフ構築** | **O(M)** | M は制約の数。 |
| **SCC の抽出** | **O(V + E)** | V = 2*N 個の変数、E = 2*M 本のエッジ。 |
| **値の割り当て** | **O(V)** | 各変数の SCC ID を比較。 |
| **合計** | **O(N + M)** | 線形時間で解決可能！ |

3 つの変数の制約（3-SAT）が **NP 完全**（高速な解法が見つかっていない）であるのと対照的に、2-SAT は驚くほど効率的に解ける「スイートスポット」です。

## 💻 LOGIC & PSEUDO-CODE：2-SAT ソルバー

```javascript
class TwoSATSolver {
    constructor(numVariables) {
        this.n = numVariables;
        this.adj = Array.from({ length: 2 * n }, () => []);
    }

    // 制約 (X or Y) を追加
    // i, j はインデックス。2*i を Xi、2*i + 1 を !Xi とする
    addClause(i, isITrue, j, isJTrue) {
        let u = isITrue ? 2 * i : 2 * i + 1;
        let notU = isITrue ? 2 * i + 1 : 2 * i;
        let v = isJTrue ? 2 * j : 2 * j + 1;
        let notV = isJTrue ? 2 * j + 1 : 2 * j;
        
        this.adj[notU].push(v);
        this.adj[notV].push(u);
    }

    solve() {
        // 1. Tarjan を実行して SCC ID を取得
        const sccIds = getSCC(this.adj); 
        const result = new Array(this.n);

        for (let i = 0; i < this.n; i++) {
            if (sccIds[2 * i] === sccIds[2 * i + 1]) return null; // 矛盾発生
            // 割り当て：SCC ID が大きい方（トポロジカル順序）を採用
            result[i] = sccIds[2 * i] < sccIds[2 * i + 1];
        }
        return result;
    }
}
```

## 🧠 LEETCODE STRATEGY：論理ゲーム

2-SAT の問題は、「ペア」「選択肢」「スケジュール」といったストーリーの中に隠れていることが多いです。

1. **Course Schedule (#207)**：より単純なバージョン（DAG チェック）ですが、2-SAT として構成することも可能です。
2. **Possible Bipartition (#886)**：BFS/DFS で解けますが、本質的にはノードがグループ A または B のどちらかに属するという 2-SAT 問題です。
3. **Number of Ways to Build Sturdy Wall (#2184)**：論理的な含意を用いて簡略化できる複雑な制約の問題です。
4. **カスタム 2-SAT**：「各アイテムについて 2 つのオプションから 1 つを選ぶ」かつ「競合するペアがある」という問題を探してみてください。

## 🎯 EXAM & INTERVIEW LOGIC：競技プログラミングと面接の戦略

- **「線形時間」の議論**：面接で問題を 2-SAT と特定できれば、勝利は目前です。2-SAT は O(V+E) で解けるが、3-SAT は NP 完全であることを説明できれば、深い理論的知識をアピールできます。
- **トポロジカル順序**：Tarjan のアルゴリズムはノードをトポロジカル順序の逆順で訪問することを忘れないでください。これが SCC ID に基づいて値を割り当てる理由です。
- **ソクラテス・ゲート**：なぜ `(X or Y)` は `!X -> Y` を意味するのですか？
  - *回答*：`X` が FALSE の場合、全体の節 `(X or Y)` を TRUE にするためには、`Y` が **必ず** TRUE でなければならないからです。`X` がすでに TRUE なら、`Y` は何でも構いません。これが論理的含意の定義です。

## 💼 PROFESSIONAL CONTEXT：エンジニアリングへの応用

- **ハードウェア検証 (EDA)**：デジタル回路設計に矛盾が含まれていないか、正常に動作するかを検証するために使用されます。
- **依存関係の解決 (Dependency Resolvers)**：最新のパッケージマネージャーは、リクエストされたライブラリのバージョンの組み合わせが有効であることを確認するために SAT ソルバー（または 2-SAT などの変種）を使用します。
- **スケジューリングシステム**：「会議室 A はイベント 1 とイベント 2 を同時に開催できない」「もしイベント 1 が午前なら、イベント 2 は午後でなければならない」。これらは 2-SAT に最適な制約です。

## 🛡️ RELIABILITY & BUGS：マスターへのアドバイス

1. **インデックスの混乱**：2-SAT の最も難しい部分は、変数 `i` を `2i` と `2i+1` にマッピングすることです。インデックスの管理には細心の注意を払ってください。
2. **グラフのサイズ**：含意グラフには **2N** 個のノードがあることを忘れないでください。十分なメモリを確保してください。
3. **空の制約**：制約がない問題は常に充足可能です。エッジケースを正しく処理しましょう。
