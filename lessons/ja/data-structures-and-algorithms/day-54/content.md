# リンク・カット木 (LCT)：動的連結性の極意 🌲⛓️

**Day 54**へようこそ。これまでのレッスンでは、固定された木（静的木）上の問題を扱う方法を学びました。しかし、現実の世界は常に変化しています。ネットワーク接続が切れ、新しい道路が建設され、ファイルはあるフォルダから別のフォルダへと移動されます。

今日は、**リンク・カット木（Link-Cut Tree / リンク・カット木）**について学びます。これは、森林（独立した木の集合）における **動的連結性（Dynamic Connectivity）** の問題を扱うための最も強力なデータ構造です。

---

## 🪝 THE HOOK：「海底ケーブルとケーブル切断事故」

あなたがグローバルな光ファイバーネットワークを管理していると想像してください。各都市はノードであり、各ケーブルはエッジです。このネットワークは、多くの独立した木からなる森林の構造を持っています。
いつでも以下のことが起こり得ます：
1.  **Link**: 都市Aと都市Bを結ぶ新しいケーブルが設置される。
2.  **Cut**: ケーブルが切断される（または撤去される）。
3.  **Query**: CとDの間のパス上にある総伝送容量を計算したり、最大負荷のステーションを探したりする。

もしHLD（重軽分割）を使うなら、`Link` や `Cut` が発生するたびに構造全体を再構築する必要があり、これには **$O(N)$** かかります。1日に数百万件のイベントが発生する場合、システムは崩壊してしまいます。
**リンク・カット木** を使えば、これらすべての操作（Link, Cut, Path Query）をわずか **$O(\log N)$** （ならし計算量）で実行できます。これは、最先端の動的ネットワークルーティングシステムの背後にあるテクノロジーです。

---

## 🎭 ANALOGY：LEGOブロックとジッパー

1.  **LEGO (Link & Cut)**: LEGOブロックを思い浮かべてください。2つのブロックをつなげて大きな構造物を作ったり、いつでもそれらを分離したりできます。LCTは、森林のコンポーネントを柔軟に組み立てることを可能にする、LEGOの「アルゴリズム版」です。
2.  **ジッパー (Preferred Edges)**: パスを管理するために、LCTは「優先エッジ（Preferred Edges）」という概念を使用します。木の中のある道に沿ってジッパーを引いているところを想像してください。一度に一つの道だけが「開いて」おり、そこへ最速でアクセスできます。別の道に行きたいときは、その枝にジッパーを「スライド」させます。

LCTは、木をいくつかの断片（パス）に分解し、それぞれの断片を **Splay Tree（スプレー木）** で管理します。

---

## ⚙️ UNDER THE HOOD：LCTの内部構造

リンク・カット木は、**補助木（Auxiliary Trees）** と呼ばれる非常に巧妙な構造を使用します。

### 1. パス分解 (Preferred Paths)
LCTは、元の木（Represented Tree）を、重なりのないパスである **優先パス（Preferred Paths）** に分割します。
-   各パスは一つの **Splay Tree** に保存されます。
-   Splay Tree内での順序は、元の木におけるノードの深さに基づきます。Splay Treeの左の子は、実際の木においてより浅い（根に近い）ノードです。

### 2. Access操作（LCTの鍵）
最も重要な操作は `access(v)` です。これは以下のことを行います：
-   実際の木の根からノード `v` までの優先パスを作成する。
-   `access(v)` の後、`v` はそのパスを代表する Splay Tree において最も深いノードになります。

### 3. Link, Cut, Evert
-   **Evert(v)**: ノード `v` を実際の木全体の根にします。
-   **Link(u, v)**: ノード `u` と `v` を接続します（異なる木に属している場合）。
-   **Cut(u, v)**: `u` と `v` を結ぶエッジを削除します。

---

## 📊 BIG-O ANALYSIS：音速のパフォーマンス

| 操作 | 計算量 | 解説 |
| :--- | :--- | :--- |
| **Access(v)** | **$O(\log N)$** (ならし) | Splay Tree の性質に基づきます。 |
| **Link(u, v)** | **$O(\log N)$** (ならし) | `evert`、`access`、接続を含みます。 |
| **Cut(u, v)** | **$O(\log N)$** (ならし) | `evert`、`access`、切断を含みます。 |
| **パス・クエリ** | **$O(\log N)$** (ならし) | `access` 後、結果は Splay Tree の根にあります。 |

**Master Tip**: LCTのすべての操作はならし $O(\log N)$ です。これは現在、最も高速な動的木データ構造の一つです。

## 💻 LOGIC & PSEUDO-CODE：LCTノードとAccessの実装

その複雑さから、LCTは通常、Splay Treeノードを保存するために静的配列を使用します。

```javascript
class LCTNode {
    constructor() {
        this.ch = [0, 0]; // 左の子、右の子 (0はnull)
        this.p = 0;       // 親
        this.rev = 0;     // 反転のための遅延タグ (evert用)
        this.val = 0;     // ノードの値
        this.sum = 0;     // パス上の合計値（または所望の結果）
    }
}

let tr = Array.from({ length: MAXN }, () => new LCTNode());

/**
 * Access操作: 根からuまでのパスを構築する
 */
function access(u) {
    for (let last = 0; u; last = u, u = tr[u].p) {
        splay(u);      // uを現在のSplay Treeの根に持ってくる
        tr[u].ch[1] = last; // 優先エッジをlastに変更する
        pushUp(u);     // 合計値（sum, min, maxなど）を更新する
    }
}

/**
 * uを実際の木の根にする
 */
function evert(u) {
    access(u);
    splay(u);
    tr[u].rev ^= 1; // パスを代表するSplay Treeを反転させる
    pushDown(u);
}
```

## 🧠 LEETCODE STRATEGY：「動的な木」の問題

LCTは以下のケースで非常に有用です：

1.  **木の上での動的連結性**: 複数の Link/Cut 操作の後に `findRoot(u) === findRoot(v)` を確認する。
2.  **動的な木のパス・クエリ**: エッジが常に変化する状況で、パス上の合計/最小/最大を計算する。
3.  **森林の動的直径**: 木が接続されていく過程で、各木の直径を求める。
4.  **LeetCode #???**: 重心分解と同様に、これらの問題は通常、競技プログラミングの最高レベル（World Finalなど）に位置します。しかし、LCTを知ることは、**Splay Tree** と **木分解** の組み合わせを深く理解することに繋がります。

## 🎯 EXAM & INTERVIEW LOGIC：IPA ＆ 外資テックの戦略

-   **IPA 基本情報技術者 (科目B)**: 動的なグラフ上の操作について問われる可能性があります。LCTは、一つのデータ構造（Splay Tree）を使って別のデータ構造（Tree）を管理するという、連携の極致です。
-   **外資テック アーキテクト面接**: 「依存関係が常に変化する、木構造のマイクロサービス依存関係を管理するシステムをどのように設計しますか？」
    -   *回答*: 「**リンク・カット木（LCT）**を使用します。この構造は、ノード間の Link と Cut 操作を対数時間でサポートし、同時に非常に高速なパスクエリを可能にします。」
-   **ソクラテス・ゲート**: なぜLCTはAVLや赤黒木ではなく、Splay Treeを使うのですか？
    -   *回答*: Splay Treeは柔軟性が高く（ならし計算量の性質）、静的な平衡二分探索木のように厳格な平衡維持のための回転を必要とするものよりも、パスの分割や結合の操作が実装しやすいためです。

## 💼 PROFESSIONAL CONTEXT：ネットワーク・インフラとグラフィックス

-   **Software-Defined Networking (SDN)**: ネットワークコントローラは、デバイスの故障や追加によってネットワーク構造が変化した際に、ルーティングテーブルを管理するためにLCTを使用します。
-   **動的シーングラフ**: 主要なゲームエンジンにおいて、3D空間でオブジェクト同士が「アタッチ」されたり「デタッチ」されたりする際の親子関係の管理。
-   **インクリメンタル・アルゴリズム**: コンピュータグラフィックスにおいて、移動するオブジェクトの **凸包（Convex Hull）** を計算する際、動的な境界セグメントを管理するためにLCTが使われることがあります。

## 🛡️ RELIABILITY & BUGS：マスターへのアドバイス

1.  **Revタグの管理**: `evert` 操作はバイナリ反転に依存しています。タグが正しく伝播するように、子ノードにアクセスする前に必ず `pushDown` することを忘れないでください。
2.  **IsRootチェック**: LCTのSplay Treeにおいて、あるノードが補助木の根である（実際の根ではない）ことは、`tr[tr[u].p].ch[0] !== u && tr[tr[u].p].ch[1] !== u` で判定されます。これはLCT実装で最も多いミスの一つです。
3.  **サイクル防止**: `Link(u, v)` を呼び出す前に、`findRoot(u) === findRoot(v)` を確認して、サイクル（閉路）が形成されないようにしてください。
