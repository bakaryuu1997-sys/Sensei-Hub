# ナップサック問題の変位：最適選択の芸術 🎒

**Phase 6**へようこそ：あなたの習得への旅の最終段階です。これまでに、動的計画法（DP）の基礎を探索してきました。今日は、プログラミングの世界で「マスター」を目指すなら避けて通れない伝説的な問題：**ナップサック問題 (The Knapsack Problem)** に向き合います。

これは単なる一つの問題ではありません。経済、物流、そしてソフトウェアエンジニアリングにおける数千もの最適化問題を解決するための**思考フレームワーク**なのです。

---

## 🪝 THE HOOK：なぜ「欲張り（Greedy）」では失敗するのか？

あなたが10kgまでしか入らないバッグを持って、宝物庫に忍び込んだ泥棒だと想像してください。
- **ダイヤモンド**: 2kg、価値 1,000万円
- **金塊**: 5kg、価値 1,200万円
- **高級香木**: 6kg、価値 1,500万円

もし**欲張り法 (Greedy)** で考えると：
1. まず単価が最も高いダイヤモンドを選びます：残り8kg。
2. 次に、入る中で最も高い香木を選びます：合計 1,000 + 1,500 = 2,500万円。バッグはいっぱいです。
しかし、もし金塊＋香木を選んでいたら？ 合計 1,200 + 1,500 = 2,700万円。**こちらのほうが価値が高いのです！**

欲張り法が失敗するのは、全体的な最適な組み合わせを考慮せず、その瞬間の最善の選択肢しか見ないからです。**DP**を使えば、何百万年も計算にかけずに、すべての組み合わせを賢く「試す」ことができます。

---

## 🎭 ANALOGY：一点物のアンティークショップ vs スーパーマーケット

ナップサックの変位を理解するために、3つのシナリオを想像してください：
1. **0/1 ナップサック**: 一点物ばかりのアンティークショップでの買い物です。各アイテムは一つしかありません。選択肢は「取る」か「取らない」のどちらかです。
2. **個数制限なし (Unbounded) ナップサック**: スーパーマーケットのようなものです。各アイテム（例：ペットボトルの水）には無限の在庫があります。バッグの容量が許す限り、0、1、2、あるいは100個でも取ることができます。
3. **個数制限付き (Bounded) ナップサック**: 限定版アイテムを買うようなものです。各アイテムには特定の数量（例：レゴセットは3つまで）があります。

## ⚙️ UNDER THE HOOD：2次元状態とメモリの最適化

ナップサックの本質は、各ステップでの決断です：「$i$番目のアイテムを、現在の容量$j$のバッグに入れるべきか、否か？」

### 1. 漸化式 (Recurrence Relation)
`dp[i][j]`を、$i$番目までのアイテムを考慮したときの容量$j$のバッグでの最大価値とします。
- **アイテム$i$を取らない場合**: `dp[i][j] = dp[i-1][j]`（前のステップの結果を維持）。
- **アイテム$i$を取る場合**（`weight[i] <= j`のときのみ）: `dp[i][j] = value[i] + dp[i-1][j - weight[i]]`（そのアイテムの価値 ＋ 残りの容量での最適な結果）。

**最終結果**: `dp[i][j] = max(取らない, 取る)`。

### 2. 空間最適化：ローリング配列
`dp[i]`が`dp[i-1]`だけに依存していることに気づきましたか？ 高価な2次元行列は必要ありません。**1次元配列** `dp[j]` を用意し、古いデータを上書きしないように特別な順序で更新するだけで十分です。

### 3. 個数制限付きの謎：バイナリ分割 (Binary Splitting)
**個数制限付き (Bounded) ナップサック**では、各アイテムに数量 $c_i$ があります。
- **素朴な方法**: $c_i$ 個のアイテムをすべて別々の 0/1 アイテムとして扱います。しかし、$c_i = 1000$ の場合、非常に遅くなります。
- **マスターの方法**: **バイナリ分割**を使います。$c_i$ を 2 のべき乗のグループに分けます：$1, 2, 4, 8, \dots, rem$。
例えば、13個のアイテムがある場合、`1, 2, 4, 6` のグループに分けます。これらの組み合わせで 1 から 13 までのあらゆる数量を表現できます。
結果：個数制限付きを、アイテム数が **$O(\log c_i)$** しか増えない 0/1 ナップサックに変換できます。究極の最適化です。

## 📊 BIG-O ANALYSIS：トレードオフの力

ナップサック問題は **NP困難** な問題ですが、DPを使えば **擬多項式時間 (Pseudo-polynomial time)** で解くことができます。

| 実装方法 | 時間計算量 | 空間計算量 | 解説 |
| :--- | :--- | :--- | :--- |
| **素朴な再帰** | **O(2^n)** | O(n) | Nが大きいと使い物にならない。 |
| **DP (2次元行列)** | **O(n * W)** | O(n * W) | 高速だがメモリを大量に消費。 |
| **DP (1次元配列)** | **O(n * W)** | **O(W)** | **マスターにとっての黄金律。** |

*Wはバッグの容量、nはアイテム数。*

## 💻 LOGIC & PSEUDO-CODE：0/1 vs 個数制限なし

実装上の唯一の違いは、**ループの方向**にあります。

### 0/1 ナップサック（各アイテム1つまで）
```javascript
// 同じアイテムを2回使うのを避けるため、Wから0へ逆順にループ
for (let i = 0; i < n; i++) {
    for (let j = W; j >= weight[i]; j--) {
        dp[j] = Math.max(dp[j], value[i] + dp[j - weight[i]]);
    }
}
```

### 個数制限なし (Unbounded) ナップサック
```javascript
// 同じアイテムを何度も使えるように、0からWへ正順にループ
for (let i = 0; i < n; i++) {
    for (let j = weight[i]; j <= W; j++) {
        dp[j] = Math.max(dp[j], value[i] + dp[j - weight[i]]);
    }
}
```

## 🛡️ RELIABILITY & BUGS：マスターへの助言

1. **1次元ループの方向バグ**: これは致命的です。0/1 ナップサックで正順ループを回すと、個数制限なしになってしまいます。ループの方向に細心の注意を。
2. **初期化**: 「最大価値」なら `0` で初期化。「最小コイン数」なら `Infinity` で初期化。「通り数」なら `dp[0] = 1` とします。
3. **W の制約**: $W > 10^7$ を超える場合、通常のDPはメモリ不足で破綻します。その場合は **Meet-in-the-middle** などのテクニックが必要になります。
