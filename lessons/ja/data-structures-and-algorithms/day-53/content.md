# 永続的データ構造：歴史をその手に ⏳

**Day 53**へようこそ。通常、配列の値や木のノードを変更すると、古い値は永遠に失われます。しかし、**Master DSA**の世界では、時間を巻き戻す力を持つことができます。

今日は、**永続的データ構造（Persistent Data Structures / 永続的構造）**を紹介します。これは、過去のすべてのバージョンが保存され、何千回もの更新が行われた後でも、いつでも過去の状態を呼び出すことができるデータ構造です。

---

## 🪝 THE HOOK：「なぜGitは何百万ものバージョンのコードを保存できるのか？」

すべての開発者が使うツール、**Git**について考えてみてください。
-   10,000行のファイルの中の、わずか1行を変更したとします。
-   Gitは新しいバージョンを作るためにプロジェクト全体をコピーしたりはしません（そんなことをすれば、ディスク容量はすぐにテラバイト級になってしまいます）。
-   その代わりに、Gitは変更された部分だけを保存し、それ以外の変更されていない部分は前のバージョンから**再利用（Reuse）**します。

これが**永続性（Persistency）**の原理です。アルゴリズムにおいて、ある配列があり、「今日の午前10時時点での区間 [L, R] の合計値はいくらだったか？」というクエリを投げたい場合、**永続セグメント木（Persistent Segment Tree）**が必要になります。これは、極めて最適化されたメモリ消費でデータの履歴を管理できる「魔法」です。

---

## 🎭 ANALOGY：台帳とコピー

1.  **通常の方法（上書き）**: 紙にインクで書くようなものです。修正するときは、二重線で消すか上から書き直す必要があり、元のバージョンは失われます。
2.  **永続的構造（Path Copying）**: 家系図を想像してください。新しい子供が生まれたとき、家系図全体を書き直す必要はありません。その子から父、そして祖父へと続く新しい枝だけを描き加えます。家系図の他の部分（叔父や従兄弟など）は、古い図面からそのまま共有されます。
    -   変更に至るまでの「道筋（Path）」のためにのみ、追加の「紙」を消費します。

DSAでは、ノードを直接修正する代わりに、根（Root）からその変更箇所に至るパス上のノードを新しく作成し、それ以外のノードは古いバージョンをそのまま「指し示す（Point）」ようにします。

---

## ⚙️ UNDER THE HOOD：永続セグメント木 (PST)

最も一般的な構造は、**永続セグメント木（Persistent Segment Tree / PST）**です。

### 1. パス・コピー（Path Copying）の仕組み
位置 `idx` の値を更新する場合：
-   対応する葉ノード（Leaf）を修正する代わりに、新しい葉ノードを作成します。
-   その葉の親も、新しい葉を指し示すために新しく作成される必要があります。
-   このプロセスが根まで繰り返されます。
-   各更新によって、一つの**新しい根（New Root）**が誕生します。
-   `idx` から根までのパス上にないノードは、再利用されます（単に古いバージョンのノードへの参照を持たせるだけです）。

### 2. メモリ効率
-   標準的なセグメント木は $2N$ 個のノード（$O(N)$）を持ちます。
-   各更新で新しく作成されるノードは $O(\log N)$ 個です。
-   $M$ 回の更新を行っても、総メモリ使用量は $O(N + M \log N)$ です。これは、木全体を $M$ 個コピーする場合（$O(M \times N)$）に比べて圧倒的に小さい数値です。

---

## 📊 BIG-O ANALYSIS：時間の価値

| 操作 | 計算量 | 解説 |
| :--- | :--- | :--- |
| **初期ツリー構築** | **$O(N \log N)$** | バージョン0の木を構築する。 |
| **更新 (Version K)** | **$O(\log N)$** | `log N` 個の新しいノードを作成する。 |
| **クエリ (Version K)** | **$O(\log N)$** | `root[K]` を根とする木に対してクエリを実行する。 |
| **更新ごとの空間量** | **$O(\log N)$** | 全体コピーに比べて極めて効率的。 |

## 💻 LOGIC & PSEUDO-CODE：PSTノードの実装

```javascript
class PSTNode {
    constructor(val = 0, L = null, R = null) {
        this.val = val;
        this.L = L;
        this.R = R;
    }
}

let roots = []; // すべてのバージョンの根を保持する

/**
 * 指定したインデックスの値を更新し、新しい根を返す
 */
function update(prevNode, l, r, idx, newVal) {
    // 古いノードからコピーして新しいノードを作成
    let newNode = new PSTNode(prevNode.val, prevNode.L, prevNode.R);
    
    if (l === r) {
        newNode.val = newVal; // 新しい葉ノード
        return newNode;
    }

    let mid = Math.floor((l + r) / 2);
    if (idx <= mid) {
        // 左の枝だけ新しく作成し、右の枝は古い方を指す
        newNode.L = update(prevNode.L, l, mid, idx, newVal);
    } else {
        // 右の枝だけ新しく作成し、左の枝は古い方を指す
        newNode.R = update(prevNode.R, mid + 1, r, idx, newVal);
    }
    
    newNode.val = newNode.L.val + newNode.R.val;
    return newNode;
}
```

## 🧠 LEETCODE STRATEGY：「タイムトラベル」問題

永続的データ構造は、以下のような問題に対する「究極の武器」です。

1.  **LeetCode #1146. Snapshot Array**: 「スナップショット」の作成と、特定の時点での値の取得をサポートする配列の実装。大きな $N$ の制限に対して、PSTは理想的な解法です。
2.  **K-th Smallest Element in a Range**: 区間 [L, R] 内で $k$ 番目に小さい数を探す。PSTと座標圧縮（Coordinate Compression）を組み合わせる典型的な問題です。
3.  **履歴付きの範囲クエリ**: 「時間」や「バージョン」という変数が追加されたあらゆる問題。
4.  **永続的DSU**: 集合をマージした後の、過去のある時点での連結性を確認するために使用されます。

## 🎯 EXAM & INTERVIEW LOGIC：IPA ＆ 外資テックの極意

-   **IPA 基本情報技術者 (科目B)**: バージョン管理や不変（Immutable）なデータ構造について問われることがあります。PSTは、データ構造上での**関数型プログラミング**的思考の具現化です。
-   **外資テック 首席面接**: 「ユーザーデータの『タイムトラベル』機能をサポートする必要があります。メモリを最も節約するにはどうすればよいですか？」
    -   *回答*: 「データ構造を**永続的（Persistent）**な形で実装します。上書きの代わりに**パス・コピー（Path Copying）**手法を用い、変更されたノードのみを新しく作成し、古いメモリを再利用します。これにより、任意のバージョンの状態を $O(\log N)$ でクエリできます。」
-   **ソクラテス・ゲート**: なぜPSTでは、セグメント木でよく使われる配列形式（`2*i`, `2*i+1`）を使わないのですか？
    -   *回答*: 木の構造が動的に変化し、バージョン間でノードを共有するためです。ポインタや参照を使用することで、異なるバージョンのノードを柔軟かつ自然に繋ぎ合わせることができます。

## 💼 PROFESSIONAL CONTEXT：スナップショット、ブロックチェーン、Git

-   **データベース・スナップショット (MVCC)**: **PostgreSQL** や **MySQL** などのデータベースでは、新しいデータが書き込まれている間も古いデータをクエリできるようになっています（多版型同時実行制御）。その根底にある原理は、永続的アーキテクチャに則っています。
-   **ブロックチェーンのステート・ツリー**: **Ethereum** では、すべての全アカウントの状態が巨大な **Merkle Patricia Trie** に保存されています。新しいブロックは変更部分だけを保存し、残りは前のブロックの古い部分を指し示します。これは巨大な永続ツリーです！
-   **Undo/Redo システム**: **Photoshop** や **Figma** などのグラフィックソフトは、数千個のオブジェクトの変更履歴を、シーングラフの永続的なバージョンを保存することで管理しています。
-   **Gitの内部構造**: Hookで述べた通り、Gitは数百万行のコードを効率的に管理するために、永続的な有向非巡回グラフ（DAG）アーキテクチャを使用しています。

## 🛡️ RELIABILITY & BUGS：マスターへのアドバイス

1.  **メモリ管理**: 更新ごとに $\log N$ 個のノードが作成されます。更新が多すぎるとRAMが不足する可能性があります。見積もりとして、$N=10^6$ に対して `M * 20` ノード程度を想定してください。静的配列を使用する場合は、最初から十分なサイズを確保してください。
2.  **無限再帰**: PSTの再帰では、常に `l === r` の条件をチェックして葉で停止するようにしてください。
3.  **座標圧縮**: PSTを使用する前（特に $k$ 番目の要素の問題）は、木が深くなりすぎないように、大きな値を [1, N] の範囲に圧縮してください。
