# 計算幾何学：空間を操るアルゴリズム 📐

このフェーズ最後の技術探求へようこそ。テーマは **計算幾何学 (Computational Geometry)** です。

これまでのアルゴリズムの多くは、離散的な整数や論理的な関係（グラフ）を扱ってきました。しかし、計算幾何学が扱うのは **「空間」** です。これは、次のような現代技術の目に見えないエンジンとなっています。
-   **Google Maps**: 湾曲した地球表面上の最短経路を算出。
-   **ゲーム物理**: 弾丸がキャラクターの当たり判定（Hitbox）に接触したかの判定。
-   **ロボット工学**: ロボットが壁に衝突せずに移動するための経路計画。
-   **自動運転**: 数千の点群（Lidar）を処理して車線や障害物を識別。

今日は、無味乾燥に見える数学公式を、強力で高速なコードへと変換する方法を学びます。

## 🪝 THE HOOK：「コンピュータは描かない。計算するのだ」

シューティングゲームのコードを書いていると想像してください。プレイヤー（点A）と壁（線分BC）があります。弾丸が壁を突き抜けたかどうかを、コンピュータはどうやって知るのでしょうか？
もし `sin`, `cos`, `tan` といった複雑な三角関数を使えば、計算は遅くなり、**精度誤差 (Rounding Error)** によるバグが多発するでしょう。

DSAのマスターは三角関数を使いません。代わりに **ベクトル (Vector)** と **外積 (Cross Product)** を使います。これが、毎秒数百万ピクセルを正確に、かつ高速に処理するための極意です。

---

## 🎭 ANALOGY：輪ゴムと釘

**凸包 (Convex Hull)**：木板の上にランダムに釘が打たれている様子を想像してください。ここで、巨大な輪ゴムをすべての釘を囲むように広げてから、手を離します。輪ゴムは縮まり、一番外側にある釘にぴったりと張り付きます。
この輪ゴムが作る形が **「凸包」** です。内側にある釘は、輪ゴムの形には影響しません。

アルゴリズムにおいて、凸包は点集合の「境界」を見つけるために使われます。これは空間データ分析や画像処理における核心的なスキルです。

## ⚙️ UNDER THE HOOD：ベクトルの威力

### 1. 外積 (2D幾何学の切り札)
2D幾何学において最も重要な道具です。2つのベクトル $A(x_1, y_1)$ と $B(x_2, y_2)$ に対して：
$\text{外積} = x_1 \cdot y_2 - x_2 \cdot y_1$
-   結果が $> 0$：ベクトルBはベクトルAの **左側** にある（反時計回り）。
-   結果が $< 0$：ベクトルBはベクトルAの **右側** にある（時計回り）。
-   結果が $= 0$：2つのベクトルは **一直線上 (Collinear)** にある。

**なぜこれが「マスター級」なのか？**: 割り算も平方根も使わず、掛け算と引き算だけで完結するからです。整数演算であれば、非常に高速で、かつ誤差が全く発生しません。

### 2. 線分の交差判定
2つの線分 $AB$ と $CD$ が交差するかを判定するには、$C$ と $D$ が直線 $AB$ に対して反対側にあり、かつ $A$ と $B$ が直線 $CD$ に対して反対側にあるかをチェックします。これを4つの外積計算（方向判定）で行います。

### 3. 靴紐の公式 (Shoelace Formula)
多角形の頂点座標 $(x_i, y_i)$ が与えられたとき、その **面積** を計算する非常にシンプルな方法です。
$\text{面積} = \frac{1}{2} | \sum (x_i y_{i+1} - x_{i+1} y_i) |$

## 📊 BIG-O ANALYSIS：空間の計算量

| アルゴリズム | 計算量 | 解説 |
| :--- | :--- | :--- |
| **点の内外判定** | **$O(N)$** | $N$ は多角形の頂点数（光線放射法）。 |
| **凸包計算** | **$O(N \log N)$** | 点のソート時間が支配的（モノトーン・チェーン法）。 |
| **最近点対問題** | **$O(N \log N)$** | 分割統治法を用いて、最も近い2点を探す。 |
| **交差判定** | **$O(1)$** | 数回の掛け算と引き算のみ。 |

## 💻 LOGIC & PSEUDO-CODE：方向判定と交差

```javascript
/**
 * 戻り値:
 * 0: 一直線上
 * 1: 時計回り (右折)
 * 2: 反時計回り (左折)
 */
function getOrientation(p, q, r) {
    let val = (q.y - p.y) * (r.x - q.x) - (q.x - p.x) * (r.y - q.y);
    if (val === 0) return 0;
    return (val > 0) ? 1 : 2;
}

/**
 * 線分 p1q1 と p2q2 が交差するか判定
 */
function doIntersect(p1, q1, p2, q2) {
    let o1 = getOrientation(p1, q1, p2);
    let o2 = getOrientation(p1, q1, q2);
    let o3 = getOrientation(p2, q2, p1);
    let o4 = getOrientation(p2, q2, q1);

    // 一般的なケース
    if (o1 !== o2 && o3 !== o4) return true;

    // 特殊なケース（点が一重線上にある場合など）
    // ... onSegment() 等の追加ロジック ...
    return false;
}
```

## 🧠 LEETCODE STRATEGY：幾何学的思考

1.  **Erect the Fence (#587)**: 凸包の直接的な実装問題。古典的なHard問題です。
2.  **Max Points on a Line (#149)**: 一直線上の最大点数。誤差を避けるため、傾きを最大公約数 (GCD) を使った既約分数で管理するのがコツです。
3.  **Valid Boomerang (#1037)**: 3点が三角形を作るか（一直線上にないか）を判定します。
4.  **Self Crossing (#335)**: 経路が自身と交差するか。幾何学的ロジックの優れた練習台です。
5.  **Circle and Rectangle Overlap (#1401)**: 円と長方形の当たり判定。

## 🎯 EXAM & INTERVIEW LOGIC：IPA試験とMAANGの戦略

-   **IPA 基本情報技術者試験 (科目B)**: 日本の試験では、多角形の面積計算や、ある点が指定された範囲内にあるかの判定がよく出題されます。**靴紐の公式**や**距離の公式**を確実にマスターしましょう。
-   **面接でのプロのヒント**: まずデータ型を確認しましょう。「座標は整数ですか、それとも浮動小数点数ですか？」。浮動小数点数の場合は、精度誤差を考慮して `EPSILON = 1e-9` を使った比較を行うことを即座に提案しましょう。
-   **Socratic Gate**: プログラミングにおいて、直線を $y = mx + c$ で表現しないのはなぜですか？
    *   **回答**: 垂直な直線 ($x = k$) を表現できないからです（傾き $m$ が無限大になるため）。マスターは **一般形** ($ax + by + c = 0$) か **ベクトル形式** を使います。

## 🛡️ RELIABILITY & BUGS：マスターへの警告

1.  **浮動小数点の精度**: 最大の敵です。JSでは `0.1 + 0.2` は `0.3` になりません。常に `Math.abs(a - b) < EPSILON` を使いましょう。
2.  **一直線上の点 (Collinear Points)**: 凸包アルゴリズムでバグの原因になりやすいです。辺上の点を含めるのか、頂点のみにするのかを事前に定義しましょう。
3.  **オーバーフロー**: 座標を掛け合わせる際（例: $x_1 \cdot y_2$）、結果が 32bit の限界を超えることがよくあります。**BigInt** や `long long` を使用してください。
