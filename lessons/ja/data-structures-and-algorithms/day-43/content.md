# 組合せ論と確率：数え上げの技術 🎲

**Day 43** へようこそ。高度なシステム設計やアルゴリズムの最適化において、私たちは次のような問いに頻繁に遭遇します。
-   メッシュネットワーク内で、パケットをAからBへ送る経路は何通りあるか？
-   10個のタスクを3つの同一のワーカーに分散させる方法は何通りあるか？
-   2つのノードが同時に故障した場合、分散システムがデッドロックに陥る確率はどのくらいか？

すべての可能性を書き出そうとすれば、失敗に終わるでしょう。その数は数兆、あるいはそれ以上に達することがあるからです。今日は、**「数えずに数える」** 技術である **組合せ論 (Combinatorics)** と、**「見えずして予測する」** 技術である **確率 (Probability)** をマスターします。

## 🪝 THE HOOK：「宇宙の原子数を超える選択肢」

10桁のパスワード（英数字）を想像してください。作成可能な組み合わせの数は、約 **3.7垓（がい）** 通りにものぼります。
また、52枚のトランプをシャッフルしたとき、その並び順（$52!$）はあまりにも膨大で、ビッグバン以来、毎秒シャッフルし続けたとしても、同じ並び順に二度と出会うことはないでしょう。

組合せ論をマスターすれば、コードを書く前に問題の複雑さを見積もることができます。状態数が多すぎる場合、**「全探索 (Brute Force)」** ではなく **「動的計画法 (DP)」** や **「貪欲法 (Greedy)」** を使うべきだと即座に判断できるようになります。

---

## 🎭 ANALOGY：レストランのメニューと宝くじ

1.  **順列 (Permutation)**：レースを想像してください。ゴールした順番（1位、2位、3位）が重要です。順序が変われば、結果も変わります。
2.  **組合せ (Combination)**：ピザのトッピングを3つ選ぶことを考えてください。（チキン、マッシュルーム、オニオン）を選んでも、（オニオン、マッシュルーム、チキン）を選んでも、出来上がるピザは同じです。順序は関係ありません。
3.  **確率 (Probability)**：宝くじを引くようなものです。100万枚のチケットがあり、あなたが1枚持っているとき、当選する可能性は100万分の1です。

アルゴリズムにおいて、組合せ論は「状態空間」の計算に、確率は **「確率的アルゴリズム (Randomized Algorithms)」** の最適化に使用されます。

---

## ⚙️ UNDER THE HOOD：数え上げの「黄金法則」

### 1. 和の法則と積の法則
-   **和の法則**: 事象Aが $n$ 通り、事象Bが $m$ 通りあり、これらが同時には起こらない場合、全体では $n + m$ 通りとなります。
-   **積の法則**: 事象Aが $n$ 通りあり、そのそれぞれに対して事象Bが $m$ 通りある場合、全体では $n \cdot m$ 通りとなります。

### 2. 順列と組合せ
-   **順列 ($P(n, k)$)**: $n$ 個から $k$ 個を選んで並べる（順序あり）: $P(n, k) = \frac{n!}{(n-k)!}$
-   **組合せ ($C(n, k)$)**: $n$ 個から $k$ 個を選ぶ（順序なし）: $C(n, k) = \frac{n!}{k!(n-k)!}$
    -   これは **二項係数** と呼ばれ、パスカルの三角形の基礎となります。

### 3. 重複組合せ (仕切り棒のテクニック)
$n$ 個の区別のつかないアイテムを、$k$ 個の区別できる箱に入れる高度な手法です。
-   **公式**: $\binom{n+k-1}{k-1}$
-   **応用**: CPUサイクルの割り当て、メモリブロックの分配、サーバー負荷の分散計算など。

### 4. 期待値 ($E[X]$)
多くの試行を繰り返したときに得られる「平均的な」結果です。アルゴリズムでは、**平均的な計算量 (Average Case Complexity)** の分析に役立ちます。
-   $E[X] = \sum (\text{値} \times \text{その値が出る確率})$

## 📊 BIG-O ANALYSIS：数値が爆発するとき

| 概念/アルゴリズム | 計算量 | 用途 |
| :--- | :--- | :--- |
| **階乗計算 ($n!$)** | **$O(n)$** | $n$ が非常に小さい場合のみ。 |
| **二項係数 (DP)** | **$O(n \cdot k)$** | オーバーフローを防ぎつつ $C(n, k)$ を算出。 |
| **確率DP** | **$O(N^2)$** | $N$ ステップ後の遷移確率を計算。 |
| **モンテカルロ法** | **$O(\text{Iterations})$** | 大量の試行により確率を近似的に推定。 |

## 💻 LOGIC & PSEUDO-CODE：DPによる組合せ計算

巨大な階乗による **整数オーバーフロー** を避けるため、パスカルの恒等式 $C(n, k) = C(n-1, k-1) + C(n-1, k)$ に基づく動的計画法を使用します。

```javascript
/**
 * パスカルの三角形を用いた nCr の計算 (DP)
 * 計算量: O(n*k), 空間量: O(k)
 */
function combinations(n, k) {
    if (k < 0 || k > n) return 0;
    if (k === 0 || k === n) return 1;
    if (k > n / 2) k = n - k; // 対称性の性質を利用

    let dp = new Array(k + 1).fill(0);
    dp[0] = 1;

    for (let i = 1; i <= n; i++) {
        // 1次元配列で空間を節約するため、後ろから更新
        for (let j = Math.min(i, k); j > 0; j--) {
            dp[j] = dp[j] + dp[j - 1];
        }
    }
    return dp[k];
}
```

## 🧠 LEETCODE STRATEGY：数え上げと確率のパターン

1.  **Unique Paths (#62)**: 本質的に $C(m+n-2, n-1)$ の問題です。「右」か「下」かを選ぶ問題に帰結します。
2.  **Combinations (#77)**: すべての組合せを列挙します。**Backtracking (バックトラッキング)** を使用。
3.  **Climbing Stairs (#70)**: 通常はDPで解きますが、1段跳びと2段跳びの組合せの数え上げとしても解釈できます。
4.  **Knight Probability in Chessboard (#688)**: 典型的な「確率DP」の問題です。
5.  **カタラン数 (Catalan Numbers)**: 「正しい括弧列の数」や「二分探索木のパターン数」を数える際に現れる数列です。

## 🎯 EXAM & INTERVIEW LOGIC：IPA試験とMAANGの戦略

-   **IPA 基本情報技術者試験 (科目B)**: 日本の試験では、**条件付き確率**や**期待値**が頻出です。公式 $P(A|B) = \frac{P(A \cap B)}{P(B)}$ を確実に覚えましょう。
-   **面接でのプロのヒント**: 「何通りあるか？」と聞かれたら、以下の3つのレイヤーで考えます。
    1.  **数式 (Formula)**: 数学的な解があるか？（最善）
    2.  **DP**: 重複する部分問題を数え上げられるか？（最適）
    3.  **バックトラッキング**: 具体的に「列挙」する必要があるか？（$N$ が小さい場合のみ）
-   **Socratic Gate**: 「Unique Paths」問題で、移動の合計回数が常に $(m-1) + (n-1)$ になるのはなぜですか？
    *   **回答**: どの経路を通っても、ゴールに到達するためには必ず「下」へ $m-1$ 回、「右」へ $n-1$ 回移動しなければならないからです。問題は、その全ステップの中でいつ「右」に移動するかというインデックスを選ぶことに他なりません。

## 💼 PROFESSIONAL CONTEXT：実社会における数え上げ

-   **A/Bテスト**: **Netflix** のエンジニアは、確率と $P$ 値を使用して、新しいUIデザインが実際にユーザーエンゲージメントを高めたのか、それとも単なる偶然の結果（誤差）なのかを判断します。
-   **ロードバランシング**: **確率的ロードバランシング** (例: The Power of Two Choices) は、各サーバーの状態をすべて把握することなく、確率を利用してトラフィックを均等に分散させます。
-   **誤り訂正符号 (ECC)**: 現代のSSDやRAMは、ハミング符号などの組合せ論的な符号を使用して、宇宙線などで発生するビット反転を検出し、自動的に修正します。
-   **フィンテック (リスク管理)**：**モンテカルロ・シミュレーション** は、市場の数百万通りの組合せシナリオを実行し、投資ポートフォリオの損失確率を予測します。

## 🛡️ RELIABILITY & BUGS：マスターへの警告

1.  **整数オーバーフロー**: 階乗は爆発的に増加します（$20!$ で 64bit の限界を超えます）。必ず **BigInt** を使うか、組合せの公式の途中で早めに割り算を行ってください。
2.  **浮動小数点の精度**: 確率の計算で小さな値を何度も掛け合わせると、結果が 0 になる **アンダーフロー (Underflow)** が発生します。その場合は、**「対数確率 (Log-probability)」**（掛け算をログの足し算に変換）を使用してください。
3.  **境界値 (Off-by-One)**: $k=0$ や $n=k$ のケースを必ずテストしてください。組合せ論において、これらは最もミスが発生しやすいポイントです。
