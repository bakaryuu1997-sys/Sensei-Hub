# 9日目: プロフェッショナルな開発環境の構築（Foundry & Hardhat）

9日目へようこそ！これまでの8日間、私たちはブラウザ上の **Remix IDE** を使ってコードを書き、テスト実行してきました。Remixは短いコードを素早く検証するのには非常に素晴らしいツールですが、現実の本格的なWeb3プロジェクト（互いに連携する数十のスマートコントラクト、何百もの複雑なユニットテスト、自動デプロイプロセスなどを含むもの）においては、手元のコンピュータ上にプロフェッショナルなローカル開発環境を構築することが不可欠です。

本日は、現在世界で最も広く使われている2大開発ツールである **Hardhat** と **Foundry** について学び、実際にゼロから完全なFoundryプロジェクトを構築していきます。

---

## 1. 王座をかけた争い：Hardhat vs Foundry

かつては、**Hardhat**（Node.jsベース、JavaScript/TypeScriptでテストを記述）が圧倒的な王者として君臨していました。しかし、ここ数年、特に2026年現在においては、**Foundry**（Rust製、Solidityで直接テストを記述）が急成長し、プロの開発チームやセキュリティ監査（オーディット）のプロフェッショナルが推奨する業界のゴールドスタンダードとなっています。

### 主要機能の比較表:

| 機能・特徴 | Hardhat | Foundry（推奨） |
| :--- | :--- | :--- |
| **テスト記述言語** | JavaScript / TypeScript | **Solidity**（新しくJSを学ぶ必要なし） |
| **コンパイル速度** | 遅い（Node.jsエンジン） | **極めて高速**（Rust製コンパイルエンジン） |
| **テスト実行速度** | 普通 | **超高速**（マルチスレッドによる並行実行） |
| **ローカルノード（仮想ウォレット）** | Hardhat Network | Anvil（超軽量なローカルノード） |
| **付属ツール** | Hardhat CLI | `forge`（ビルド/テスト）, `cast`（CLI操作）, `anvil`（ノード） |
| **ファズテスト（Fuzz Testing）** | 外部ライブラリの統合が必要 | **デフォルトで強力なサポートを搭載** |

> 💡 **なぜFoundryが支持されるのか？**
> テスト（ユニットテスト）をSolidity言語そのもので記述できるため、開発者はJavaScriptとSolidityの間で思考を切り替える（コンテキストスイッチする）ストレスから解放されます。さらに、FoundryはRustでエミュレートされたEVM上で直接実行されるため、Hardhatと比較して10〜100倍も高速に動作します。

## 2. Foundryのインストール手順

お使いのコンピュータ（Linux、macOS、およびWindowsのWSL2に対応）にFoundryをインストールする方法を説明します：

### ステップ 1: Foundryup インストーラーのダウンロード
ターミナルを開き、以下のコマンドを実行してFoundryのバージョン管理ツールである `foundryup` をダウンロードします：

```bash
curl -L https://foundry.paradigm.xyz | bash
```

### ステップ 2: Foundry ツールのインストール
上記のコマンドが完了したら、ターミナルを再起動するか、環境変数を再読み込みするコマンド（例: `source ~/.zshrc` または `source ~/.bashrc`）を実行し、以下のコマンドを実行します：

```bash
foundryup
```

このコマンドを実行すると、以下の4つのコアツールが自动的にダウンロードされ、インストールされます：
1. **`forge`**: プロジェクト管理、コンパイル、テスト実行、スマートコントラクトのデプロイを行うツール。
2. **`anvil`**: Hardhat NetworkやGanacheに相当する、ローカルなEthereumブロックチェーンエミュレータ（ローカルノード）。
3. **`cast`**: コードを書くことなく、ブロックチェーンから直接データを照会したり、ターミナル上でトランザクションを送信したりできる便利なCLIツール。
4. **`chisel`**: ターミナル上で直接Solidityのコードを実行し、素早く文法テストができるREPL環境。

インストールが成功したかどうかを、以下を入力して確認します：
```bash
forge --version
```

## 3. Foundryプロジェクトの作成と構造の分析

それでは、最初のWeb3プロジェクト用のディレクトリを作成し、Foundryプロジェクトを初期化しましょう：

```bash
mkdir sensei-foundry-dapp
cd sensei-foundry-dapp
forge init --no-git
```
*（ここでは `--no-git` を使用しています。これは、現在の Sensei Hub プロジェクト自体がすでに巨大なGitリポジトリの一部であるためです。）*

### 生成されたディレクトリ構造の分析:

```text
sensei-foundry-dapp/
├── lib/               # Gitサブモジュールとして外部ライブラリ（OpenZeppelinなど）を格納するディレクトリ
├── src/               # メインのスマートコントラクトを格納する場所 (.sol)
│   └── Counter.sol
├── test/              # ユニットテストファイルを格納する場所 (.sol)
│   └── Counter.t.sol
├── script/            # デプロイスクリプトファイルを格納する場所 (.sol)
│   └── Counter.s.sol
└── foundry.toml       # プロジェクトの設定ファイル（コンパイラバージョン、オプティマイザ、RPCキーなど）
```

---

## 4. Forge CLI による開発ワークフローのマスター

### 4.1. プロジェクトのコンパイル（Compiling）
`src/` ディレクトリ内のすべてのSolidityファイルをコンパイルするには、以下を実行します：

```bash
forge build
```
Foundryのコンパイルは極めて高速です。コンパイル結果のファイル（ABIやバイトコード）は `out/` ディレクトリに保存されます。

### 4.2. デフォルトテストの実行（Testing）
Foundryは自動的に `Counter.t.sol` というテストファイルを作成します。以下のコマンドを実行してテストを実行してみましょう：

```bash
forge test
```
ターミナル上にすべてのテストケースがパスしたことを示す緑色の表示が出力されます！

## 5. Anvil エミュレータと Cast CLI ツールの使いこなし

自分のコンピュータ上でローカルなEthereumブロックチェーンを起動し、本物のハッカーのように対話する方法を説明します。

### 5.1. Anvil によるローカル Ethereum ネットワークの起動
新しいターミナルウィンドウを開き（現在開いているウィンドウはそのまま残しておきます）、以下のコマンドを入力します：

```bash
anvil
```

Anvilは即座に `http://127.0.0.1:8545` で動作するローカルブロックチェーンネットワークを起動します。
* テスト用に、それぞれ **10,000仮想ETH** が入った **10個のダミーウォレットアカウント** と、その秘密鍵（Private Key）を自動的に生成します。
* *注意:* 開発作業中は、このAnvilを実行しているウィンドウを開いたままにしておいてください。

### 5.2. Cast CLI を使用したブロックチェーンの照会
元のターミナルウィンドウに戻り、`cast` ツールを使用して起動したAnvilネットワークと通信してみましょう：

* **Anvilの最初のアカウント（アカウント1）の残高を取得する:**
    ```bash
    cast balance 0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266 --rpc-url http://127.0.0.1:8545
    ```
    *出力結果:* `10000000000000000000000` （単位はWei、10,000 ETHに相当します）。

* **Wei から Ether に変換する:**
    ```bash
    cast to-dec 10000000000000000000000
    ```

* **アカウント1からローカルのアカウント2に 10 ETH を送信する:**
    ```bash
    cast send 0x70997970C51812dc3A010C7d01b50e0d17dc79C8 --value 10ether --private-key 0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80 --rpc-url http://127.0.0.1:8545
    ```
    ターミナル上に、トランザクションハッシュ、ブロック番号、詳細なガス代などの情報を含む新しいトランザクションがAnvilによって記録されるのを確認できます！
