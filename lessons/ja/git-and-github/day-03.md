# Day 3: GitHubでの作業 & SSHキーの設定

Day 3にようこそ！これまでの2日間で、ローカルマシン上でのGitの基本操作をマスターしました。しかし、現代のソフトウェア開発の本質は「共同作業」にあります。今日は、ローカルにある「プロジェクトのスナップショット」を世界最大のソースコード共有プラットフォームである **GitHub** にアップロードする方法を学びます。

---

## 1. Git と GitHub の違い：混同を解消しよう！

多くの初心者がGitとGitHubを同じものだと誤解しています。以下のシンプルな比喩で覚えておいてください。
*   **Git** はあなたの「日記帳」です（履歴を保存し、オフラインで動作し、ローカルマシン上に存在します）。
*   **GitHub** はその日記帳が集まる「図書館」または「SNS」です（リポジトリをオンラインでホストし、他の人がコードを閲覧したり共同開発したりできるようにします）。

他にも **GitLab** や **Bitbucket** といった優れたプラットフォームが存在しますが、GitHubはすべての開発者が知っておくべき業界標準の「ゴールドスタンダード」です。

---

## 2. 認証方式：HTTPS vs SSH

ローカルマシンからGitHubにコードをアップロード（プッシュ）する際、GitHubはあなたがアクセス権限を持つ本人であるかを確認する必要があります。その主な方法は以下の2つです。

1.  **HTTPS：** リモートサーバーとやり取りするたびに、ユーザー名と特別なパスワード（パーソナルアクセストークン - PAT）の入力を求められます。毎回入力するのは面倒であり、現在プロの開発現場では推奨されていません。
2.  **SSH (Secure Shell)：** 業界のベストプラクティスです。あなたのコンピューター上で安全な暗号鍵ペアを生成します。その「南京錠」にあたる **公開鍵（Public Key）** をGitHubに登録し、その「鍵」にあたる **秘密鍵（Private Key）** を自分のコンピューターに安全に保管します。以降、パスワードを入力することなく、PCとGitHubの間で自動的かつ安全に相互認証が行われます。

**本日は、より実用的で安全な「SSH」での設定を行います。**

---

## 3. SSHキーの設定手順（ステップバイステップ）

コマンドラインの操作が初めてでも心配ありません。以下の手順に沿って、順番に実行してください。

### ステップ 1: 既存のSSHキーがあるか確認する
ターミナルまたはGit Bashを開き、以下を実行します。
```bash
ls -al ~/.ssh
```
`id_rsa.pub` や `id_ed25519.pub` のようなファイルが表示された場合、すでに鍵ペアが作成されています。フォルダが空であるか、エラーが表示された場合はステップ2に進んでください。

### ステップ 2: 新しいSSHキーペアを生成する
以下のコマンドを実行します（メールアドレス部分はご自身のGitHubのものに置き換えてください）。
```bash
ssh-keygen -t ed25519 -C "your_email@example.com"
```
*   「Enter file in which to save the key」と表示されたら、そのまま **Enter** キーを押します（デフォルトの保存場所に設定されます）。
*   「Enter passphrase」と表示されたら、そのまま **Enter** を押して空欄にする（便利さを優先）か、任意のパスワードを入力して鍵を暗号化（セキュリティを最大化）します。

### ステップ 3: SSHキーをssh-agentに登録する
バックグラウンドで起動している認証エージェントを起動し、鍵を登録します。
```bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
```

### ステップ 4: 公開鍵をGitHubアカウントに追加する
作成した公開鍵の内容を表示し、コピーします。
```bash
cat ~/.ssh/id_ed25519.pub
```
*出力結果は `ssh-ed25519 ...` で始まります。この文字列全体をコピーしてください。*

1.  [GitHub](https://github.com) にログインします。
2.  画面右上のプロフィール画像をクリックし、**Settings**（設定）を選択します。
3.  左サイドバーの **SSH and GPG keys** をクリックします。
4.  **New SSH key** をクリックします。
5.  **Title** に分かりやすい名前を入力します（例: "My Personal Laptop"）。
6.  **Key** の入力欄に、先ほどコピーした公開鍵の文字列を貼り付けます。**Add SSH key** をクリックします。

### ステップ 5: SSH接続のテスト
コンピューターとGitHubが正しく接続できているか検証します。
```bash
ssh -T git@github.com
```
「*Hi username! You've successfully authenticated, but GitHub does not provide shell access.*」というメッセージが表示されれば、**設定は完璧に成功しています。**

## 4. ローカルリポジトリとGitHubの連携

Day 2で作業したローカルリポジトリ `git-fundamentals` に戻りましょう。

### ステップ 1: GitHubで新規リポジトリを作成する
1.  GitHub画面右上の「**+**」アイコンをクリックし、**New repository** を選択します。
2.  リポジトリ名をローカルのフォルダ名と同じ `git-fundamentals` に設定します。
3.  公開範囲を **Public** に設定します。
4.  「Add a README file」「Add .gitignore」「Choose a license」のチェック欄は**すべて外したまま**にします（ローカルにすでにファイルがあるため）。
5.  **Create repository** をクリックします。

### ステップ 2: リモートリポジトリのURLを登録する
GitHub上にリポジトリが作成されると、`git@github.com:username/git-fundamentals.git` のようなSSH用のURLが表示されます。これをコピーして、ローカルのターミナルで以下を実行します。

```bash
git remote add origin git@github.com:username/git-fundamentals.git
```
*   `git remote add`: 新しいリモートリポジトリとの関連付けを行います。
*   `origin`: リモートサーバーを参照するためのデフォルトの別名（エイリアス）です（任意の名前を付けられますが、99%の開発現場で `origin` が使用されます）。

---

## 5. コードをGitHubにプッシュする

ローカルのコミット履歴をGitHubに送信（プッシュ）します。

```bash
git push -u origin main
```
*   `-u origin main`: `-u` (upstream) フラグは、ローカルの `main` ブランチと `origin` 上の `main` ブランチの関連付けをGitに記憶させます。次回からは、単に `git push` と入力するだけでプッシュできるようになります。

GitHub上のリポジトリページをリロード（F5）してみましょう。ファイルとコミット履歴が反映されているはずです！

---

## 6. 重要な同期用コマンド

チーム開発や複数のパソコンで作業を行う際、以下の同期用コマンドを頻繁に使用します。

### git clone (クローン)
新しいPCで作業を開始する際、`git init` は行いません。GitHubからリポジトリの履歴全体をダウンロードするために以下を実行します。
```bash
git clone git@github.com:username/git-fundamentals.git
```

### git fetch vs. git pull
*   **git fetch:** リモートリポジトリから最新の変更情報を取得しますが、ローカルの作業ディレクトリには**反映（マージ）しません**。マージ前に変更内容を確認できるため安全です。
*   **git pull:** リモートから変更を取得し、ローカルブランチに**自動的にマージ**します（`pull` = `fetch` + `merge`）。便利ですが、競合（コンフリクト）が発生することがあります。

---

## 7. リモート設定のトラブルシューティング

**エラー: `fatal: remote origin already exists`**
*   **原因:** すでに `origin` という名前でリモートURLが登録されています。
*   **対策:** `git remote remove origin` を実行して既存の設定を削除し、正しいURLで再登録してください。

**エラー: `Permission denied (publickey)`**
*   **原因:** SSHエージェントが起動していないか、GitHubに登録した公開鍵が間違っています。
*   **対策:** ステップ3およびステップ4を見直し、公開鍵が正しくGitHubの設定に貼り付けられているか再確認してください。
