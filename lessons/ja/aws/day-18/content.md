# 🪝 THE HOOK: 「一歩間違えれば大惨事」

あなたがデジタル銀行のシステムを運営していると想像してください。顧客が「送金」ボタンを押したとき、システムは以下のステップを踏む必要があります：
1. 残高チェック
2. 送金元から減額
3. 送金先へ増額
4. SMS で通知

もしステップ 3 が成功したのに、ステップ 4 が失敗したら？ 顧客は不安になります。さらに悪いことに、ステップ 2（減額）が完了したのに、ネットワークエラーでステップ 3（増額）が失敗したら？ あなたの銀行は信頼を失い、法的なトラブルに発展するでしょう。

あなたが必要としているのは、次のような保証ができる「コーディネーター」です。「もしどこかのステップでエラーが起きたら再試行し、それでもダメならすべてを元に戻す（ロールバック）」。そして、Bot の攻撃からシステムを守る「門番」も必要です。

**Amazon API Gateway** と **AWS Step Functions** へようこそ。一方は頼れる「門番」、もう一方はすべてのワークフローを自在に操る「指揮者」です。

# 🎭 ANALOGY: 5 つ星レストランの運営

**5 つ星レストラン**での体験を想像してみましょう。

### 💂‍♂️ 1. API Gateway: ホールのマネージャー
- 客は勝手に厨房に入ることはできません。まずは入り口でマネージャーに会う必要があります。
- マネージャーの仕事：
    - **VIP チェック（認証）**: 「予約はありますか？」
    - **入店制限（スロットリング）**: 「満席ですので、5 分ほどお待ちください」
    - **案内（ルーティング）**: 「寿司の方は A 席へ、お酒の方は B 席へどうぞ」

### 📜 2. Step Functions: 標準調理手順書 (SOP)
- 注文を受けた後、Step Functions は詳細な設計図になります：
    - ステップ 1: 野菜を洗う。
    - ステップ 2: **もし** 新鮮なら調理へ。**もし** 萎びていたら新しい野菜を取りに行く（リトライ）。
    - ステップ 3: 加熱する。
    - ステップ 4: 5 分間冷ます（待機）。
    - ステップ 5: 盛り付ける（完了）。
- もし途中でボヤが起きたら、この設計図は客に謝罪し、返金処理を行います（エラーハンドリング）。

# ⚙️ UNDER THE HOOD: 技術ディープダイブ

### 1. Amazon API Gateway
- **API タイプ**: REST API（フル機能）、HTTP API（高速・安価）、WebSocket（リアルタイム）。
- **セキュリティ**: API キー、Cognito、WAF 統合。
- **スロットリング**: バックエンドを保護するためにリクエスト数を制限。

### 2. AWS Step Functions
- **ステートマシン**: ワークフローのフローチャートをコード（ASL）で記述。
- **ステート（状態）**: Task（実行）、Choice（分岐）、Parallel（並列）、Map（繰り返し）、Wait（待機）。
- **耐久性**: 各ステップの履歴を記録。どこでエラーが起きたか即座に特定可能。

### 3. 2026 年最新アップデート: オーケストレーションの新時代 🚀
- **Amazon Q in Step Functions**: 2026 年、複雑な ASL コードを書く必要はありません。「1 億円以上の注文なら上司の承認が必要、それ以下なら自動承認するフローを作って」と伝えるだけで、AI が図面とコードを自動生成します。
- **Distributed Map 2.0**: S3 上の数百万個のファイルを驚異的なスピードで同時に並列処理。ビッグデータ処理が「朝飯前」になります。
- **API Gateway mTLS 2.0**: 2026 年のセキュリティ標準。すべての内部 API で相互 TLS（mTLS）認証を要求し、巧妙ななりすまし攻撃を遮断します。

# ☁️ AWS IN PRACTICE / INTERVIEW

**実務シチュエーション：** 「なぜ Lambda から別の Lambda を直接呼び出すのではなく、Step Functions を使うのですか？」

**マスターアーキテクトの回答例：**
「Lambda が Lambda を呼ぶ『チェイニング』はアンチパターンです。呼び出された Lambda がエラーになると、呼び出し側も待機時間が発生し課金が続きます。またロールバック処理が極めて困難です。Step Functions を使えば、調整ロジックと処理ロジックを分離できます。2026 年の技術なら、**Visual Studio Code SDK** を使って実行中のステップを可視化しながらデバッグできるため、修正時間を数時間から数分に短縮できます。」

# 🔦 CASE STUDY: Comic Relief と寄付ナイトを支える「指揮者」の力

**背景:** Comic Relief は英国の大手慈善団体で、「Red Nose Day」というイベントを開催しています。生放送中、数百万人が一斉に寄付のメッセージを送ったり電話をかけたりします。トラフィックは一瞬にして毎秒 0 から 30 万リクエストにまで跳ね上がります。

**課題:** 各寄付（Donation）は複雑なプロセスです：1. カード認証 → 2. 決済 → 3. 寄付総額の更新 → 4. 確認メール。従来のサーバーでは、司会者が寄付を呼びかけた瞬間にシステムがダウンしてしまいます。

**API Gateway & Step Functions による解決策（2026 年基準）:**
1.  **API Gateway - 屈強な門番**: モバイルアプリやウェブサイトからの全リクエストを受け付けます。手動設定なしで数十万の同時リクエストを捌くよう自動スケーリングします。**Request Validation** 機能により、不正な形式のリクエストを入り口で弾き、内部の Lambda 負荷を軽減します。
2.  **Step Functions - 一貫性の保証**: 寄付プロセスを **ステートマシン** として設計。「決済」に成功しても「総額更新」に失敗した場合、Step Functions が自動的に **補償トランザクション（Compensating Transaction）** を起動して返金を行い、財務データの正確性を絶対的に維持します。
3.  **Distributed Map 2.0 の活用**: イベント終了後、数百万通の領収書 PDF を出力する必要があります。Step Functions は **Distributed Map 2.0** を使い、数千の Lambda を並列稼働させることで、5 分以内に全領収書の発行を完了させました。

**BrSE への教訓:** 日本の顧客は「トランザクションの一貫性」を非常に重視します。決済や予約などのプロジェクトでは、Step Functions を提案することで、堅牢なアーキテクチャ思考をアピールしましょう。

### 🚀 Master Architect Pro-Tips

> **Tip 1 — Usage Plans で収益化**: API Gateway では **Usage Plans** と **API キー** を作成できます。自社 API を「無料プラン（100回/日）」「ゴールドプラン（1万回/日）」のようにパッケージ化して販売でき、超過分は AWS が自動でブロックします。

> **Tip 2 — WAF でスパム対策**: API Gateway を「裸」で置かないでください。前に **AWS WAF** を配置し、特定の国からの Bot や SQL インジェクション、XSS 攻撃を遮断しましょう。

> **Tip 3 — API 用には Express Workflows を優先**: Step Functions には Standard と Express の 2 種類があります。5 分以内で終わる高速な API 処理には **Express Workflows** を選びましょう。コストが大幅に安くなり、パフォーマンスも向上します。

> **Tip 4 — 「二重決済問題」の回避**: 顧客が決済ボタンを 2 回押してしまったとき、2 回課金されないようにするには？ API Gateway の **Idempotency（べき等性）** 機能と Step Functions を組み合わせ、一意の `client_token` でチェックを行います。
