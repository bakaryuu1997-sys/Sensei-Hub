# 🪝 THE HOOK

2000年代、ウェブアプリや企業の基幹システムを動かそうとしたときの「悪夢」のようなプロセスを覚えていますか？まずハードウェアを調査し、デルやHPといったメーカーに電話して見積もりを取り、決済手続きを行い、製品がオフィスに届くまで2〜4週間待つ必要がありました。

サーバーが届いたら届いたで、腰を痛めながらパーツを組み立て、ドライバーを一つずつインストールし、最初の1週間でメモリが抜けたりファンが壊れたりしないように祈る日々でした。もし会社が急成長して2倍の処理能力が必要になったら？またあの「拷問」のようなプロセスを最初から繰り返さなければなりません。すべてが手作業で、コストがかかり、極めて非効率でした。

**仮想化（Virtualization）** (#(Virtualization)) と **クラウドコンピューティング** の時代へようこそ。

**Amazon EC2** を使えば、かつて数ヶ月かかっていたプロセスが、今やわずか**60秒**と数回のクリックだけで完了します。膨大なデータを処理するためのスーパーコンピュータ並みのマシンも、個人ブログを動かすためのラズベリーパイのような小さなマシンも、自由自在に「召喚」できます。サーバーに埃が溜まって故障したり、電源がショートしたりする心配はもう不要です。あなたが考えるべき唯一のことは、**「このマシンでどんなソフトウェアを動かしたいか？」** だけです。

# 🎭 ANALOGY (現実世界の例え)

EC2 (Elastic Compute Cloud) を理解するために、難解なコンピュータの話は一旦忘れて、旅行のために乗り物を借りることを考えてみましょう。

### 🚗 旧モデル：自家用車の所有 (オンプレミス)
ディーラーに行って車を買い取ります。最初に多額の費用を支払う必要があります。保険、駐車場、定期的なメンテナンスもすべて自分持ちです。週に1時間しか乗らなくても、全額を支払わなければなりません。もし10人のグループで遊びに行きたくなっても、手元の4人乗りセダンは役に立ちません。新しくバスを買う必要があります。非常にコストがかかり、柔軟性に欠けます。

### 🏎️ 新モデル：レンタカー・カーシェア (Amazon EC2)
Amazon EC2は、地球上で最も巨大で近代的な**「セルフサービス型レンタカー・ステーション」**です。
- **多様な選択肢**: 燃費の良い4人乗りが必要ですか？AWSは **T4g** や **T3** インスタンスを提供します。重い荷物を運ぶ大型トラックが必要ですか？超低燃費の **Graviton 4** チップを搭載した **M7g** や **R7g** インスタンスがあります。グラフィックス処理やAI学習のためのF1レーシングカーが必要ですか？Amazonが独自設計したAIモンスター、**Trn2 (Trainium 2)** や **Inf3 (Inferentia 3)** が控えています。
- **使った分だけ支払い**: 時間単位（または秒単位）でレンタルします。使い終わったら車を返却（インスタンスを終了）すれば、すぐに支払いが止まります。
- **2026年アップデート: Gravitonの覇権**: 2026年、ARMベースの自社製チップ（Graviton 4）は業界のゴールドスタンダードとなりました。従来のIntel/AMDチップと比較して、コストを20%削減し、パフォーマンスを30%向上させることができます。会社の利益を最大化したいなら、末尾に **"g"** がつくインスタンスを優先的に選んでください。

# ⚙️ UNDER THE HOOD (ディープダイブ)

**Amazon EC2 (Elastic Compute Cloud)** は、クラウド内で安全かつ最大限の拡張性を持つ計算能力を提供します。「Elastic（弾力性のある）」という言葉こそが最も価値のあるポイントです。必要なときに膨らみ、仕事が終われば縮むことができます。

### 1. インスタンスを構成する4つのパーツ
EC2インスタンスを起動するには、以下の4つの主要コンポーネントを組み合わせます。
1.  **AMI (Amazonマシンイメージ)**: OS（Linux, Windows, MacOS）やプリインストールされたソフトウェアを含む「ひな形（テンプレート）」です。WordPressがインストール済みのサーバーが欲しいですか？WordPress AMIがあります。真っさらなLinuxが欲しいですか？Amazon Linux AMIがあります。
2.  **インスタンスタイプ**: 仮想ハードウェアの構成です。用途（CPU最適化、メモリ最適化、汎用など）に応じて、AWSは多くのシリーズ（C, M, R, T, G）を用意しています。
3.  **ストレージ (EBS)**: ネットワーク経由で接続される「ハードディスク（SSD/HDD）」です。EBS内のデータは、インスタンスを停止しても消えません。
4.  **ネットワークとセキュリティ**: IPアドレスの設定、そして最も重要な **セキュリティグループ (Security Group)** (#(Security Group)) の設定です。これは、80番（Web）や22番（SSH）といったポートを通じて、誰がサーバーに出入りできるかを制御する仮想ファイアウォールです。

### 2. 支払いモデル（「財布の火事」を防ぐ秘策）
ここを理解すれば、AWS認定試験の合格にぐっと近づきます。
-   **オンデマンド (On-Demand)**: 秒単位の支払い。最も柔軟ですが、単価は最も高くなります。テスト、開発、またはトラフィックが不安定なアプリに適しています。
-   **リザーブドインスタンス (RI)**: 1年または3年の利用をコミット（約束）します。見返りに、AWSは最大 **75%** の割引を提供します。会社の公式サイトのように、24時間365日安定して稼働するシステムに適しています。
-   **スポットインスタンス (Spot Instances)**: AWSの在庫の中で「余っている」サーバーをオークションにかける形式です。オンデマンドより最大 **90%** 安くなることもあります。ただし、他の顧客が高い値をつけた場合や、AWSがリソースを必要とした場合、2分前に通知が来て強制的に回収されます。中断しても問題のないバッチ処理などに最適です。
-   **Dedicated Hosts (専用ホスト)**: あなた専用の物理サーバーを丸ごと一台借ります。極めて高いセキュリティ要件や、厳しいソフトウェアライセンス契約がある場合に使用します。

### 3. 拡張性：エラスティシティ (#(Elasticity))
EC2は単独では動きません。通常、**Auto Scaling** と **ロードバランサー** とセットで運用されます。
- アクセスが集中すると、Auto Scalingが自動的にEC2を10台増やして負荷を分散します。
- 夜中になってユーザーが寝静まると、自動的に9台を削除してコストを節約します。これこそがクラウドの真骨頂です！

# ☁️ AWS IN PRACTICE / INTERVIEW

**実戦シチュエーション：** 「上司が今月のEC2の請求額が高すぎると怒っています。調査したところ、データベースとメインのウェブサイト用に20台のオンデマンドインスタンスを24時間365日動かしていることがわかりました。クラウドマスターとして、パフォーマンスを落とさずにコストを少なくとも40%削減する提案をしてください。」

**マスターの回答例：**
「現在、最も高価で短期間のテスト向けである『オンデマンド』モデルを使用しています。当社のデータベースとウェブサイトは24時間安定して稼働しており、ビジネスの中核です。そこで、1年契約の **リザーブドインスタンス (RI)** への切り替えを提案します。ボタン一つで設定を変更するだけで、マシンのスペックはそのままに、AWSから40〜60%の即時割引を受けられます。
さらに、一部の画像処理などのバックグラウンドタスクもオンデマンドで動いています。これらを **スポットインスタンス** に切り替えます。万が一インスタンスが回収されても、システムが自動的にキューに積み直し、後で再実行するように設計します。これにより、画像処理部分のコストをさらに90%削減できます。全体として、請求額を40〜50%削減することが容易に可能です。」

**面接のヒント:** 「EC2における **Stateful (ステートフル)** と **Stateless (ステートレス)** の違いを説明してください。」
- **回答**: ローカルディスクに直接ユーザーデータを保存しているサーバーはステートフルです。しかし、近代的なクラウド設計では、**ステートレス**な構成を優先します。つまり、EC2は計算処理だけを行い、データはデータベースやS3に保存します。これにより、データを失う心配をせずに、いつでもEC2を削除したり新しく作り直したりできるようになります。

# 🔦 CASE STUDY: AirbnbのEC2コスト削減戦略（年間500万ドルの節約）

**背景:** 2022年、世界最大の宿泊予約プラットフォームであるAirbnbは、AWSに年間1億ドル以上を費やしていました。パンデミックの影響で旅行業界が打撃を受ける中、同社のCloud Economicsチームはパフォーマンスを維持しつつコストを削減する任務を負いました。

**課題:** Airbnbのトラフィックは極端に不規則です。週末や連休のピーク時は、平日の5〜10倍に膨れ上がります。すべてをオンデマンドにすると高額になり、すべてをリザーブドインスタンスにすると閑散期に無駄が発生します。

**解決策：EC2の「3レイヤー」戦略**

1.  **レイヤー1 — 安定したベースラインのためのリザーブドインスタンス (RI):**
    - 常に必要な最低限の計算能力（約40%）を1年契約のRIで購入。
    - オンデマンドと比較して、この部分のコストを約60%削減。
2.  **レイヤー2 — 柔軟性のための Savings Plans:**
    - コンピュート Savings Plansを利用。特定のインスタンスタイプに縛られず、LambdaやFargateにも自動適用される柔軟性を確保。
    - 全体の約30%をカバーし、約40%を節約。
3.  **レイヤー3 — バッチ処理と突発的なトラフィックのためのスポットインスタンス:**
    - 画像処理、データパイプライン、検索インデックス作成などのステートレスなワークロードをスポットインスタンスで実行（最大90%安）。
    - 週末のピーク時は、Auto Scalingが2〜3分でスポットインスタンスを追加。
    - 回収された場合は自動的にオンデマンドへ切り替えて中断を回避。

**結果:**
- EC2の年間コストを **1億ドルから6,500万ドルへ削減**（35%の節約）。
- Gravitonへの移行（ARMチップへの変更）により、同等以上の性能を維持しつつさらに **20%のコストを削減**。
- スケールアウトにかかる時間を、最適化されたカスタムAMIの使用により8分から **90秒** に短縮。

**BrSEへの教訓:** 日本の顧客にEC2の最適化を提案する際は、この **「3レイヤー料金戦略」** を適用してください。ベースラインはリザーブド → 柔軟性は Savings Plans → 突発負荷はスポット。これはすべてのFinOpsエンジニアの標準的なフレームワークです。

### 🚀 Master Architect Pro-Tips

> **Tip 1 — AMIは重要な資産、軽視するべからず**: 適切に「ゴールデンイメージ（セキュリティ設定や監視エージェントが導入済み）」化されたAMIを作成しておくことで、EC2の起動からサービス開始までの時間を8分から90秒に短縮できます。これは急速なスケーリングが必要な際の大きな競争力になります。

> **Tip 2 — ユーザーデータ・スクリプトはアーキテクトの武器**: インスタンス起動時に、自動でソフトウェアをインストールしたり設定を読み込んだりするBashスクリプト（ユーザーデータ）を流し込みましょう。これにより、誰かがSSHでログインして手動設定する必要がなくなります。

> **Tip 3 — Gravitonを優先し、Intelは後回し**: 2026年、デフォルトで選ぶべきは `m7g`, `c7g`, `r7g` などのGraviton 4チップ搭載インスタンスです。Intel/AMDと比較して20%安く、30%高速です。IntelはARMで動かない特定の依存関係がある場合のみ検討してください。

> **Tip 4 — スポットインスタンスを「安かろう悪かろう」と思わない**: スポットはAWSの余剰在庫のオークションです。実際には95%以上のスポットインスタンスが中断されることなく必要な時間を完遂します。複数のインスタンスタイプやAZを組み合わせるのが、スポットを安定して使いこなすコツです。

> **Tip 5 — 「vCPU」と「物理コア」の違いを知る**: `m7g.large` は2つのvCPUを持ちますが、これは物理2コアではありません。通常、1つの物理コアはハイパースレッディングにより2つのvCPUとして見えます。Oracle DBのようにコア数でライセンス料が決まるソフトウェアを動かす際は、物理コアを制御できる Dedicated Hosts が重要になります。
