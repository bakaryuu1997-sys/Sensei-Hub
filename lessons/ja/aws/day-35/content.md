# 🪝 THE HOOK: 「東京都千代田区、大手銀行の決断」

あなたが東京・千代田区にある大手銀行の IT ディレクターだと想像してください。銀行は 30 年以上稼働しており、データは地下室にある数千台の古い物理サーバーに保存されています。
- 上司からの命令：「コスト削減とセキュリティ向上のため、今後 6 ヶ月以内にすべてを AWS へ移行せよ。」
- 恐怖：「もし 1 秒でもデータが失われたりシステムがダウンしたりすれば、日本中に謝罪（土下座）して辞任しなければならない！」

あなたは難題に直面しています。50 ペタバイトのデータ（インターネット経由なら移行に 100 年かかります）、誰も動かし方を覚えていないレガシーアプリ、そしてシステムを止めずに移行しなければならないデータベース。クラウド移行はまさに「大規模な手術」です。今日は、**AWS Migration Services** を使ってこの手術を成功させる方法を学びます。

# 🎭 ANALOGY: 「引っ越し」に例えるクラウド移行

クラウドへの移行は、住み慣れた家から新しい場所へ引っ越すようなものです：

### 🏠 1. Retire - 古いものを捨てる
- 10 年間使っていない不用品（サーバー/ソフト）を捨てて、荷物を軽くします。

### 🍱 2. Rehost (Lift-and-Shift) - 家をそのまま運ぶ
- 巨大なトラックを借りて、古い家をそのまま持ち上げ、AWS という新しい土地に置きます。早いですが、内部の構造は古いままです。

### 🏗️ 3. Replatform (Lift-and-Reshape) - 家具を新調する
- 家の骨組みは維持しつつ、古いキッチンを最新のシステムキッチン（例：RDS への移行）に交換します。

### 🚀 4. Refactor (Rearchitect) - 新築する
- 古い家を壊し、クラウドの力を最大限に引き出すモダンなスタイル（サーバーレス、マイクロサービス）で建て直します。

# ⚙️ UNDER THE HOOD: 技術ディープダイブ

### 1. 7 つのマイグレーション戦略 (7 Rs)
- **Retire/Retain**: 廃止または維持。
- **Rehost/Replatform**: そのまま移行または一部修正。
- **Relocate/Repurchase**: 移設（VMware など）または買い替え（SaaS）。
- **Refactor**: 完全に作り直し（クラウドネイティブ）。

### 2. AWS Migration Discovery & DMS
- **Migration Evaluator**: クラウド移行によるコスト削減効果を予測。
- **AWS DMS (Database Migration Service)**: ダウンタイムを極限まで抑えてデータベースを移行（CDC 技術）。
- **AWS SCT (Schema Conversion Tool)**: 商用 DB（Oracle など）からオープンソース DB（Aurora など）へスキーマを変換。

### 3. 2026 年最新アップデート: AI 主導のマイグレーション 🚀
- **Amazon Q for Migration (2026)**: AI が古いコード（COBOL や Java 6 など）を読み取り、サーバーレスアーキテクチャへの **Refactor** ルートを自動提案します。ロジックの 70-80% を自動で書き換え、移行期間を年単位から月単位へ短縮します。
- **DMS 2.0 (2026)**: AI によるデータ整合性（Data Integrity）チェックを完全自動化。数億件のレコードを AI が照合し、「100% 一致」を即座にレポートします。
- **Snowball Edge AI-Enabled**: 2026 年モデルの Snowball は AI チップを内蔵。顧客のオフィスでコピー中にデータのクレンジングやタグ付けを行い、S3 にアップロードした時点ですぐに分析可能な状態にします。

**マスターアーキテクトの回答例：**
「500TB を 100Mbps で送ると 1 年以上かかります。そこで **AWS Snowball Edge** を使用します。2026 年なら、AI 内蔵の **Compute Optimized** モデルを使用して、コピーと同時に圧縮・クレンジングを行います。2 日間でコピーを終え、配送便で AWS へ送るのが、最も速く、安全で、安価な解決策です。」

# 🔦 CASE STUDY: Expedia と 100% クラウド移行戦略

**背景:** 世界最大の旅行プラットフォームの一つである Expedia は、かつて世界中に数千台の物理サーバーを抱える複雑なシステムを運用していました。ハードウェアの保守に時間が奪われ、新興の競合他社に技術競争で遅れをとっていました。

**課題:** 数十ペタバイトの予約データと機密性の高い顧客情報を、ユーザーの検索や予約（24 時間 365 日）を止めることなく移行する必要がありました。

**モダンマイグレーションによる解決策（2026 年基準）:**
1.  **Refactor (クラウドネイティブ) 戦略の採用**: 単なる移行ではなく、コアアプリケーションを **Amazon EKS** 上の **マイクロサービス** アーキテクチャに作り直しました。**Amazon Q for Migration (2026)** を活用してレガシーな Java コードを最新の **Lambda** サービスへ自動変換し、驚異的な拡張性を手に入れました。
2.  **DMS による「止まらない」移行**: **AWS DMS** を使用して、オンプレミスの DB から **Amazon Aurora** へリアルタイムでデータを同期。完全に一致した時点で、ダウンタイム数秒でトラフィックをクラウドへ切り替えました。
3.  **Snowball による巨大データの輸送**: インターネット経由では不可能な膨大な履歴データは、大量の **Snowball Edge** デバイスを使って物理的に AWS データセンターへ運びました。

**結果:**
- 年間の運用コストを **30% 削減**。
- 新機能のリリース速度が **5 倍**（数週間から数時間へ）に向上。
- 繁忙期でも 99.99% の安定稼働を実現。

**BrSE への教訓:** クラウド移行は単なるサーバーの移動ではなく、**「思考の転換」** です。日本の顧客に対しては「安全第一」の戦略を提案しましょう。まず周辺アプリの **Rehost** から始め、信頼を得てから基幹システムの **Refactor** へ進むのがリスクを最小限に抑える定石です。

### 🚀 Master Architect Pro-Tips

> **Tip 1 — PoC (概念実証) から始める**: いきなり全システムを移行してはいけません。重要度の低い小さなアプリを「実験台」として移行し、成功体験を作ることが経営陣を説得する最大の武器になります。

> **Tip 2 — データベース移行の救世主 DMS**: 巨大な SQL ファイルをネットワーク経由でインポートしようとしないでください。DMS の **Change Data Capture (CDC)** 機能を使えば、旧 DB の変更を監視し続け、切り替えの瞬間まで同期を維持できます。

> **Tip 3 — データ転送コストに注意**: クラウドへの「流入」は無料ですが、「流出」やリージョン間の移動は高価です。マイグレーションのルートを賢く設計し、「コストの罠」を回避しましょう。

> **Tip 4 — Amazon Q による自動化 (2026)**: 2026 年、AI をコード解析に使いましょう。誰もロジックを理解していない 20 年前のアプリでも、Amazon Q が一行ずつ解説し、AWS で動かすための修正箇所を特定してくれます。
