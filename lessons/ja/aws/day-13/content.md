# 🪝 THE HOOK: 「1億人の個人情報が流出した『バケツ』の教訓」

2017 年、ある大手金融企業の S3 バケットにおける単純な設定ミスにより、1 億人分の個人情報がインターネット上に晒されました。恐ろしいことに、このデータにはパスワードすら設定されておらず、ブラウザのリンク一つで誰でも閲覧可能な状態でした。その結果は？ 巨額の制裁金、失墜した社会的信用、そして多くの幹部の辞任でした。

Day 05 の基礎編では、S3 が無限のデータを保持できる「バケツ」であることを学びました。しかし **Associate レベル**では、単にデータを「入れる」だけでなく、それを「支配」しなければなりません。

ハッカーがあなたの AWS アカウントへのアクセス権を得たとしても、ファイルの中身を決して見られないようにするにはどうすればよいか？ 戦争や大規模災害に備えて、東京から米国へデータを自動的に複製するには？

**S3 Advanced** へようこそ。ここでは、プラスチックのバケツを、難攻不落の「鉄壁の要塞」へと変貌させる方法を学びます。

# 🎭 ANALOGY: 国家の最高機密保管庫

あなたが**国家の最高機密文書を管理する責任者**になったと想像してください。

### 🔒 1. S3 Encryption（暗号化）: 魔法のインク
すべての文書は普通のインクではなく、特別な「透明インク」で書かれています。
- 誰かが文書を盗み出しても、見えるのはただの白紙です。
- あなたが持っている特定の紫外線ライト（復号キー - **KMS**）を当てたときだけ、内容が浮かび上がります。

### 👯 2. S3 Replication（レプリケーション）: 「影武者」の作成
- 東京で新しい文書が作成されるたびに、システムが自動的にスイスの地下保管庫へコピーを転送します（**クロスリージョンレプリケーション**）。
- たとえ東京が消滅しても、データは地球の裏側で安全に守られます。

### 🕵️‍♂️ 3. Storage Lens（ストレージレンズ）: インテリジェントな監視ドローン
- **Storage Lens** は、毎日報告を届けるドローンのようなものです。「5 つのバケツの鍵が開いています（公開設定）」、「このバケツはコストがかかりすぎています！」と警告してくれます。

# ⚙️ UNDER THE HOOD: 技術ディープダイブ

### 1. S3 セキュリティとガバナンス
- **パブリックアクセスブロック**: バケットをインターネットから完全に遮断する「マスターキー」。
- **バケットポリシー**: バケット全体に適用する JSON 形式のルール。
- **暗号化オプション**: SSE-S3（AWS 管理）、SSE-KMS（ユーザー管理、監査ログ付き）、SSE-C（鍵はユーザーが保持）。

### 2. パフォーマンスとレプリケーション
- **マルチパートアップロード**: 5GB を超えるファイルを分割して高速・安定してアップロードします。
- **S3 Transfer Acceleration**: AWS の専用バックボーンネットワークを使い、大陸間のファイル転送を加速します。
- **CRR（クロスリージョン）と SRR（同一リージョン）**: データのコピーを作成します（**バージョニング**の有効化が必須）。

### 3. 2026 年最新アップデート: データ革命 🚀
- **S3 Tables**: 2026 年の画期的な新機能です。S3 は単なるファイル保存場所ではなく、大規模データ分析のための高性能なデータベーステーブル（Analytics-ready）として機能するようになりました。
- **S3 Access Grants**: 新しいアクセス管理方式。何千人ものユーザーや AI エージェントに対して、数千行のポリシーを書くことなく、アイデンティティに基づいて柔軟に権限を付与できます。
- **AI 駆動の Macie**: 2026 年、Amazon Macie は AI を使って数十億のファイルを自動的に「透視」し、暗号化されていないクレジットカード番号や個人情報が見つかれば即座に警告します。

# 🔦 CASE STUDY: Capital One のデータ流出事件

**背景:** 2019 年、米大手銀行 Capital One は深刻なサイバーセキュリティ危機に直面しました。ハッカーがファイアウォールの設定ミスを突き、銀行の数千の S3 バケットにアクセスしました。

**課題:** ハッカーは複雑なパスワードを破る必要はありませんでした。サーバーに割り当てられた IAM ロールの過剰な権限を悪用し、顧客データを一括ダウンロードしたのです。

**S3 セキュリティによる解決策（2026 年基準）:**
1.  **S3 Access Grants の適用**: すべてに共通の IAM ロールを使うのではなく、個別のリクエストに対して「必要最小限」かつ「一時的（Just-In-Time）」な権限を付与します。
2.  **デフォルト暗号化と Bucket Key**: すべてのバケットがデフォルトで暗号化されるようになりました。**S3 Bucket Key** を使うことで KMS の呼び出しコストを 99% 削減し、コストを気にせず全ファイルを暗号化できます。
3.  **Amazon Macie による自動監視**: Macie が AI で常時スキャン。公開バケットに個人情報が見つかれば、自動で Lambda が起動し、即座に非公開設定へ切り替えます。

**BrSE への教訓:** 日本の顧客は個人情報の保護（P マークなど）に非常に敏感です。最後の砦として、AWS アカウントレベルでの **S3 パブリックアクセスブロック** を常に有効にするよう提案しましょう。

### 🚀 Master Architect Pro-Tips

> **Tip 1 — バージョニングはバックアップではない**: バージョニングは誤消去の復元には役立ちますが、ルート権限を奪われバケットごと消されたら防げません。究極の安全のためには、**クロスリージョンレプリケーション（CRR）**で別のアカウントにコピーを取るべきです。

> **Tip 2 — S3 Tables は未来の標準**: 大量の小さな CSV/Parquet ファイルを扱っていてクエリが遅いなら、**S3 Tables（2026 年新機能）**へ移行しましょう。メタデータ管理が自動化され、Snowflake などの専用 DB に匹敵する速度が得られます。

> **Tip 3 — Intelligent-Tiering で賢く節約**: どのファイルをいつ Glacier に移すか計算してはいけません。**Intelligent-Tiering** を使えば、アクセス頻度に応じて自動でストレージクラスを移動してくれます。

> **Tip 4 — MFA Delete で二重の守りを**: ソースコードや法的文書などの極めて重要なデータには **MFA Delete** を有効にしましょう。たとえ管理者のパスワードが盗まれても、あなたのスマホに届くワンタイムパスワードがなければファイルは削除できません。
