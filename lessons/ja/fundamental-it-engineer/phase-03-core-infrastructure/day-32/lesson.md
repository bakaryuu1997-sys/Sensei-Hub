# 🪝 1. 導入：Undefinedの罠とクロージャの神秘

**楽天** や **LINE** の採用面接を受けている自分を想像してください。面接官が次のようなシンプルなコードを差し出しました：

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 1000);
}
```

もしあなたが「 `0, 1, 2` 」と答えたなら、その面接は不合格です。実際の実行結果は `3, 3, 3` だからです。なぜでしょうか？

その答えは、JavaScriptの「背骨」とも言える2つの概念、 **実行コンテキスト (Execution Context)** と **クロージャ (Closures)** にあります。これらをマスターすれば、JSの「奇妙な」振る舞いに怯えることはなくなり、高度にカプセル化された堅牢なシステムを設計できるようになります。

# 🎭 2. 例え話：舞台の上での演劇

JavaScriptコードの実行を、 **「舞台の上での演劇」** に例えてみましょう：

1.  **舞台 (Execution Context)**: 劇が行われる物理的な空間です。
    -   **メインステージ (Global Execution Context)**: すべてが始まる場所。一つしかありません。
    -   **小道具付きのシーン (Function Execution Context)**: 俳優（関数）が登場して特定の演技をするたびに、シーンがセットアップされます。演技が終わると、シーンは解体されます。
2.  **台本 (Code)**: 俳優が従わなければならないセリフ（コード）です。
3.  **舞台裏 (Scope Chain)**: 俳優が小道具を忘れたとき、舞台裏に探しに行きます。現在のシーンになければ、メインステージまで探しに行きます。
4.  **記憶の箱 (Closures)**: 俳優がシーンを離れるときに持ち出す特別な箱です。シーンが解体された後でも、俳優はその箱の中に重要なアイテム（変数）を保持し続けます。

# ⚙️ 3. 詳細解説：2段階の実行メカニズム

すべての実行コンテキストは、2つの重要なフェーズ（段階）を経て実行されます：

### 3.1 フェーズ1：メモリ生成 (Memory Creation)
JavaScriptはコードをスキャンし、変数と関数のためのメモリ領域を確保します。
-   **`var` 変数**: `undefined` という初期値が割り当てられます。
-   **関数宣言 (Function Declaration)**: 関数全体の内容がメモリに保存されます。
-   **`let`, `const`**: 領域は確保されますが、 **一時的死区 (TDZ: Temporal Dead Zone)** に置かれます。フェーズ2で値が割り当てられるまでアクセスできません。

### 3.2 フェーズ2：実行 (Execution)
JavaScriptは上から下へ、1行ずつコードを実行します。
-   変数に実際の値を代入します。
-   関数を実行します。

**この仕組みこそが、「ホイスティング (Hoisting/巻き上げ)」を引き起こす原因です！**

# ⚙️ 4. スコープチェーン：データ探しの旅

すべてのレキシカル環境は、自身の **外部環境 (Outer Environment)** への参照を持っています。

```javascript
let a = 10;
function outer() {
    let b = 20;
    function inner() {
        console.log(a + b); // 'b'をローカルで探し、'a'を外部（グローバル）で探す
    }
    inner();
}
outer();
```
-   **マスターの思考**: スコープチェーンは、関数がどこで「呼び出されたか (Dynamic Scope)」ではなく、どこで「定義されたか (Static/Lexical Scope)」によって決まります。これにより、JavaScriptコードは予測可能で安全なものになります。

# 🚀 5. 高度なクロージャ：理論から実戦の武器へ

クロージャは単に数字を数えるためのものではありません。極限のパフォーマンス最適化のためのツールです。

### 5.1 メモ化 (Memoization/結果のキャッシュ)
メモ化は、クロージャを使用して重い計算の結果を保存し、次回の呼び出し時に再計算を防ぐ手法です。

```javascript
function heavyCalculation() {
    let cache = {}; // クロージャがこの変数を生かし続ける
    return function(n) {
        if (n in cache) {
            console.log("キャッシュから取得中...");
            return cache[n];
        }
        console.log("計算中...");
        let result = n * n; // 重い処理を想定
        cache[n] = result;
        return result;
    };
}
const memo = heavyCalculation();
memo(5); // 計算中...
memo(5); // キャッシュから取得中...
```

### 5.2 プライベートメンバとカプセル化
現代のJSではクラスの `#` を使ってプライベートフィールドを作成できますが、長年、 **クロージャ** こそがプライベートデータを生成する唯一の方法でした。

# ⚙️ 6. メモリ管理：クロージャが「重荷」になるとき

ジュニアレベルでよくある間違いは、メモリ内に巨大なオブジェクトを保持していることに気づかず、いたるところでクロージャを作成してしまうことです。

### 6.1 ガベージコレクション (GC) への意識
内部関数が外部関数のレキシカル環境への参照を保持し続けるため、内部関数が生きている限り、外部関数の変数は **決して** GCによって掃除されません。

**マスターの解決策**: クロージャ関数が不要になったら、その変数に `null` を代入してください。
`myFn = null; // 参照を断ち切り、GCがメモリを回収できるようにする。`

# ⚙️ 8. マスター詳細解説：静的スコープ vs 動的スコープ

現代の多くの言語（C、Java、JS）は **静的スコープ (Lexical Scope)** を採用しています。 **動的スコープ (Dynamic Scope)** を理解することで、なぜJSが「ユニーク」なのかが見えてきます：
-   **静的スコープ**: コードを書いた時の関数の位置に基づいて変数を探します。
-   **動的スコープ**: 実行時の「コールスタック」に基づいて変数を探します。
-   **`this` の混乱**: 多くの人が `this` は動的スコープだと思い込んでいます。実際には `this` は別のメカニズムですが、呼び出し時のコンテキストに依存するため、動的スコープに近い振る舞いをします。だからこそ、クロージャを使って `this` の値を安全に **バインド (Bind)** する必要があるのです。

# ❓ 9. Q&A：マスターの知恵

**Q: なぜ `let` を使うとループの `3, 3, 3` 問題が解決するのですか？**
*回答*: `let` は **ブロックスコープ** を作成するからです。ループの各反復（イテレーション）ごとに、メモリ上に新しい `i` が作成されます。 `var` は関数スコープしか持たないため、3つのタイムアウトすべてが、最終的に 3 になる「同じ」 `i` 変数を参照してしまいます。

**Q: クロージャを「削除」できますか？**
*回答*: 明示的に削除することはできませんが、内部関数へのすべての参照を削除することで、ガベージコレクションの対象にさせることができます。

**Q: ホイスティング（巻き上げ）は悪いことですか？**
*回答*: 言語の機能ですが、バグの原因になりやすいです。現代の標準 (ES6+) では、 `undefined` による混乱を避けるために `let/const` を使い、関数の定義順序を守ることが推奨されています。

# 📝 10. マスター演習：ロジックの達人

**Q1: 一時的死区 (TDZ) とは何ですか？**
*回答*: スコープの開始から、 `let/const` 変数が宣言されるまでの間の期間のことです。この間、変数は存在していますがアクセスすることはできません。

**Q2: 関数が定義される前に呼び出されたらどうなりますか？**
*回答*: **関数宣言** の場合は、ホイスティングにより動作します。 `var` に代入された **関数式** の場合は、 `undefined` になります。 `let/const` に代入されている場合は、 `ReferenceError` が発生します。

**Q3: クロージャを使ってクラス内に「プライベート」変数を作るには？**
*回答*: コンストラクタ内で変数を定義し、それを利用するメソッドをその中で定義します。

**Q4: 出力をトレースしてください:**
```javascript
let x = 1;
function a() {
  let x = 2;
  return function() { console.log(x); }
}
const b = a();
x = 3;
b();
```
*回答*: `2`。クロージャは、グローバルな `x` ではなく、定義された場所（ `a` の中）の `x` を記憶しています。
