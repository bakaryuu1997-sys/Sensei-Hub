# 🪝 1. 導入：メモリを喰らう怪物と「静かなる崩壊」

Reactアプリが最初はサクサク動いていたのに、1時間後には動作が重くなり、最後にはブラウザが「メモリ不足（Out of Memory）」でクラッシュしたことはありませんか？

**三菱UFJフィナンシャル・グループ (MUFG)** のような巨大金融グループのダッシュボードでは、システムは24時間365日、1MBのメモリリークも許されずに稼働し続けなければなりません。わずかなメモリリークが、数兆円の取引を処理するデータノードを崩壊させる原因になるからです。

今日、私たちはJavaScriptのメモリを「解剖」します。単に動くコードを書くだけでなく、RAM内の1バイトまでをコントロールする術を学びます。

---

# 🎭 2. 例え話：Amazonの倉庫管理

JavaScriptのメモリ管理を、 **「最新の倉庫」** に例えてみましょう：

1.  **即出し棚 (Stack)**: 本やスマホケースのように、サイズが決まっていて頻繁に使う小さな荷物です。出し入れが非常に速く、使わなくなると自動的に棚から消えます。
2.  **巨大保管庫 (Heap)**: テレビや冷蔵庫、ソファのように、大きくてサイズもバラバラな荷物です。整理整頓には時間がかかります。
3.  **清掃ロボット (Garbage Collector)**: 倉庫内を走り回るロボットです。ラベルのない荷物（誰も参照していないデータ）を見つけると、自動的に処分してスペースを空けます。

# ⚙️ 3. 詳細解説：V8エンジンのメモリ構造

JavaScriptエンジン (V8) は、メモリを主に2つの領域に分割して管理します：

### 3.1 スタックメモリ (Stack)
-   **特徴**: 非常に高速、サイズ固定。
-   **内容**: プリミティブ型データ（`string`, `number`, `boolean`, `null`, `undefined`など）と、ヒープ領域を指し示す「参照（ポインタ）」を保存します。
-   **仕組み**: LIFO（後入れ先出し）。関数が終了すると、その関数のコンテキストは即座にスタックから取り除かれ（Pop）、メモリが解放されます。

### 3.2 ヒープメモリ (Heap)
-   **特徴**: 広大、非構造的、スタックより低速。
-   **内容**: オブジェクト、配列、関数などを保存します。
-   **仕組み**: V8は **ガベージコレクション (GC)** を使用してこの領域を管理する必要があります。

# 🤖 4. ガベージコレクション：メモリの「輪廻転生」アルゴリズム

V8エンジンは、 **世代別回収 (Generational Collection)** という仕組みを採用しています：

### 4.1 新世代領域 (Young Generation)
-   新しく作成されたオブジェクトが格納されます。領域は小さく（通常1〜8MB）、 **Scavenge** アルゴリズムを使用します。メモリを半分に分け、生き残ったものだけをもう半分にコピーし、古い方を一気に消去します。非常に高速です。

### 4.2 旧世代領域 (Old Generation)
-   新世代の清掃を数回生き延びたオブジェクトは、この領域に「昇格 (Promotion)」します。ここでは **Mark-Sweep-Compact** アルゴリズムが使われます：
    -   **Mark**: ルート（グローバルやコールスタック）から到達可能なオブジェクトに印を付けます。
    -   **Sweep**: 印のないオブジェクトを削除します。
    -   **Compact**: メモリの隙間を埋めるように並べ替え、 **断片化 (Fragmentation)** を防ぎます。

### 4.3 Orinoco（オリノコ）：滑らかな動作の秘密
V8は、従来の「すべてを止めて掃除する」方式ではなく、以下の技術でスムーズな動作を実現しています：
-   **Parallel**: 複数のCPUスレッドで同時に掃除する。
-   **Incremental**: 掃除を細かく分け、UIフレームの合間に実行する（カクつきを防ぐ）。
-   **Concurrent**: バックグラウンドスレッドで掃除を行い、メインスレッドの処理を止めない。

# 🛡️ 5. WeakMap と WeakSet：静かなる守護者

なぜ `WeakMap` が必要なのでしょうか？
-   通常の `Map` では、オブジェクトをキーに使うと、そのオブジェクトは（メインコードで削除しても）Mapが存在する限り解放されません。
-   `WeakMap` は「弱い参照」を保持します。そのオブジェクトを誰も使わなくなると、GCが即座に掃除することを許可します。これは、DOMノードにメタデータを付与する際、メモリリークを恐れずに済む究極の武器です。

# ⚠️ 6. 4つの代表的なメモリリーク：静かなる泥棒

SIerのプロジェクトにおいて、システムをクラッシュさせる主な原因は以下の4つです：

1.  **意図しないグローバル変数**: グローバル変数はGCの対象になりません。
    -   *解決策*: 必ず `'use strict'` を使うか、 `let/const` でスコープを限定します。
2.  **忘れられたタイマー/コールバック**: `setInterval` はコンポーネントが破棄されても動き続けます。
    -   *解決策*: 不要になったら必ず `clearInterval()` を呼びます。
3.  **切り離された（Detached）DOMノード**: 
    ```javascript
    let element = document.getElementById("button");
    function removeButton() {
        document.body.removeChild(element);
        // 誤り: 変数 'element' が削除されたノードへの参照を保持し続けている。
        // 正解: element = null;
    }
    ```
4.  **巨大なオブジェクトを保持するクロージャ**: 内部関数が生き続けている限り、親関数の巨大な配列などもメモリに残り続けます。

# 💻 7. 高度なデバッグ：マスターの武器

### 7.1 Chrome DevTools: Memory タブ
1.  **Heap Snapshot**: 「なぜこれがまだメモリにあるのか？」という問いに答えます。
2.  **Allocation Timelines**: メモリリークが始まった正確な瞬間を特定します。
3.  **Shallow Size vs Retained Size**:
    -   **Shallow Size**: オブジェクトそのもののサイズ。
    -   **Retained Size**: そのオブジェクトと、それが保持している参照すべてが削除された場合に解放される合計サイズ。

### 7.2 オブジェクトプーリング (Object Pooling)
**MUFG** のような高頻度取引システムでは、毎ミリ秒新しいオブジェクトを作る代わりに、古いオブジェクトを使い回す「プール」を用意します。これにより、新世代領域のGC負荷を劇的に下げることができます。

# 🎯 9. 試験ロジック：マスターの知恵

**Q1: スタックに保存される変数はどれですか？**
A. `const a = { name: "JS" }` | B. `const b = 10` | C. `const c = [1, 2]`
*回答: B (プリミティブ型)。*

**Q2: なぜ V8 はメモリを「新世代」と「旧世代」に分けるのですか？**
*回答*: **「世代別仮説（ほとんどのオブジェクトはすぐに死ぬ）」** に基づいているためです。新しいものを頻繁に掃除し、長生きするものをたまに掃除する方が効率的だからです。

**Q3: 日本のシニアエンジニアはリリース前にどうメモリをチェックしますか？**
*回答*: 24時間の **負荷試験（Stress Test）** を行い、Chrome DevTools で「JS Heap」グラフを監視します。グラフが右肩上がり（ノコギリ刃のような形で底辺が上がっていく）であれば、リークがあると判断します。

**Q4: Hidden Classes（隠しクラス）とは何ですか？**
*回答*: V8がオブジェクトへのアクセスを最適化するための仕組みです。コンストラクタ内でプロパティを初期化する際、常に同じ順序で行うことでメモリを節約し、実行速度を上げることができます。

**Q5: メモリマスターへの最後のアドバイスは？**
*アドバイス*: 「メモリは OS から借りている資源である。最小限を借り、最速で返せ」。クラウド時代において、1MBの節約はそのまま顧客の運用コスト削減（Cost-saving）に直結します。
