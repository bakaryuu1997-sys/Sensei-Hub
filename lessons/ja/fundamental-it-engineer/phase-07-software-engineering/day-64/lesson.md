# 🪝 1. THE HOOK: 「完璧な計画」が崩れるとき

プロジェクトマネジメント（PM）の世界には有名な格言があります。「計画とは、決して起こらないことのリストに過ぎない」というものです。

プロジェクトが順調に進んでいると思いきや、突然テックリードが退職したり、リリース直前に顧客から「画面デザインをすべて変えてほしい」と無茶な要求が来たりします。これこそが**リスク（リスク - Risk）**が牙を剥く瞬間です。

日本では、リスクへの備えは一つの「文化」として昇華されています。リスクが起きてから対処するのではなく、数ヶ月前からそれを予測します。Day 64では、「未来を見通し」、嵐の中でもプロジェクトを安全にゴールへ導くための群衆コントロール術を学びます。

# 🎭 2. ANALOGY: 船長と大洋航海

あなたは宇宙船**Supernova**の船長だと想像してください：

1.  **プロジェクト実行 (Execution)**: 毎日、乗組員に帆を張らせ、食事を作らせ、掃除をさせる調整業務です。
2.  **リスク管理 (リスク管理)**: 救命胴衣を準備し、非常食を蓄え、嵐を避けるために天気図を常に監視することです。
3.  **コミュニケーション (Communication)**: メガホンで乗組員に指示を出し、無線で陸上（顧客）に報告して安心させることです。
4.  **変更管理 (Change Management)**: 嵐が来た際、乗組員をパニックに陥れることなく、即座に船の進路変更を命じることです。

コミュニケーションがなければ乗組員は暴動を起こし、リスク管理がなければ、たった一塗りの波で船は沈没します。

# ⚙️ 3. UNDER THE HOOD: リスク管理のプロセス (Risk Management Flow)

**FE Master**試験では、リスク管理の4つのステップを完璧に理解する必要があります：

1.  **リスク特定 (Risk Identification)**: 何が起こり得るかをすべてリストアップします。
2.  **リスク分析 (Risk Analysis)**: `影響度 × 発生確率` を計算します。
3.  **リスク対応計画 (Risk Response Planning)**: 対処案を策定します。
4.  **リスク監視 (Risk Monitoring)**: プロジェクト期間中、リスクの状態を常にモニタリングします。

**マスターの洞察**: すべてのリスクをゼロにしようとしないでください。最も「影響度」と「確率」が高いリスクにエネルギーを集中させましょう！

# 🚀 4. DEEP DIVE: マイナスのリスクに対する4つの戦略

これはIPA試験の超定番問題です：

### 4.1 回避 (Avoidance)
リスクの原因を完全に取り除くように計画を変更します。
*例*: 納期遅延の原因になりそうな難易度の高い機能をスコープから外す。

### 4.2 軽減 (Mitigation)
発生確率を下げるか、発生した際の影響（被害）を小さくします。
*例*: 専門家を呼んでチーム教育を行い、技術不足によるリスクを減らす。

### 4.3 転嫁 (Transfer)
リスクの影響を第三者に移転します。
*例*: プロジェクト保険に加入する、あるいはリスクの高い部分をアウトソーシングする。

### 4.4 受容 (Acceptance)
何もしません。発生したときにその場で対処することを認めます。
*例*: アクセス急増時にサーバーが5分間だけ重くなることを許容する。

# 🎯 5. EXAM LOGIC: IPA試験の重点 - 変更管理とコミュニケーション

**マスターが避けるべき「罠」：**
1.  **ステークホルダ (Stakeholders)**: 顧客だけでなく、開発者、ユーザー、上司など、プロジェクトに影響を受けるすべての人を指します。全員の期待値を管理しなければなりません。
2.  **コミュニケーションチャネル**: チャネルの数は `n * (n - 1) / 2` で計算されます。10人のチームなら45もの経路があります。人数が増えるほど、「情報のノイズ」は指数関数的に増えます！

**過去問サンプル（FE試験風）：**
「プロジェクトにおいて発生する可能性のある不確実な事象であって、発生するとプロジェクトの目標に影響を与えるものを何と呼ぶか。」
A. スコープ B. リスク C. マイルストーン D. クリティカルパス
*正解：B.*

# 💼 6. PROFESSIONAL CONTEXT: マスターBrSEの交渉術

重大なリスクが発生したとき、BrSEは決して「すみません、私たちのミスです」と言ってはいけません。
**マスターエンジニアのアプローチ**:
1.  即座に報告する（スピードこそ命）。
2.  3つの案（案A、B、C）を、それぞれのメリット・デメリット・コストと共に提示する。
3.  顧客の予算と優先順位に合わせて、最適な案を選んでもらう。
*マスターのスキル*: トラブルを、プロ意識と高い問題解決能力をアピールする「機会」に変えることです。

# 🚀 4.3 構成管理 (Configuration Management)

構成管理とは、プロジェクト内のすべて（ソースコード、ドキュメント、ツール）が適切にバージョン管理されている状態を保証することです。
-   **ベースライン (Baseline)**: 承認済みの成果物のバージョン（例：最終設計書）。
-   **変更管理委員会 (CCB)**: ベースラインへの変更を承認・却下する正式な組織。
-   **「スコープクリープ」の回避**: 時間やコストの調整なしに、なし崩し的にスコープ（作業範囲）が膨らんでいくのを防ぎます。

### 4.4 紛争解決 (Conflict Resolution) - 人間管理の芸術

プロジェクト実行において、対立（コンフリクト）は避けられません。マスターPMは5つの戦略を使い分けます：
1.  **協力 (Collaborating)**: 両者がWin-Winの解決策を見つける（最良）。
2.  **妥協 (Compromising)**: 互いに一歩ずつ譲り、合意に達する。
3.  **平滑化 (Smoothing)**: 相違点ではなく、共通点や合意できる部分を強調する。
4.  **強制 (Forcing)**: 権力や権限を使って解決策を押し付ける（最悪）。
5.  **撤退 (Withdrawal)**: その場では解決せず、一時的に身を引く。

# 📍 9. MASTER CASE STUDY: フィンテックプロジェクトでの「スコープクリープ」対応

**課題**: 開発の途中で、当初の契約になかった「QRコード決済機能」の追加を顧客が要求してきました。

**マスターの解決策**:
1.  PMは即座に断るのではなく、**変更管理プロセス**を動かしました。
2.  「この機能を追加すると、納期が2週間遅れ、コストが500万円増加します」と定量的に報告。
3.  顧客はリリース日を優先するため、別の優先度の低い機能を削ることに同意しました。

**結果**: チームを疲弊させることなく、重要な新機能を盛り込んで予定通りリリースできました。

# 🎯 10. EXAM LOGIC: リスクコストの計算 (EMV)

IPA試験では**期待金額価値 (EMV)** の計算が問われることがあります。
*計算問題*: リスクA（損失100万円）の発生確率は20%。リスクB（利益50万円）の発生確率は10%。プロジェクト全体のEMVは？
**計算プロセス**:
-   EMV_A = 20% * (-1,000,000) = -200,000円
-   EMV_B = 10% * 500,000 = 50,000円
-   **合計EMV = -200,000 + 50,000 = -150,000円**。プロジェクトは15万円の予備費を用意しておくべきです。

# 💼 12. PROFESSIONAL CONTEXT: 日本の「危険予知（KY）」文化

日本の製造現場やITオフィスでは、**危険予知（KY）**という文化が根付いています。
-   毎朝、チームで「今日、何か危ないこと（リスク）はあるか？」を話し合います。
-   マスターBrSEはこれをデイリースクラムに取り入れます：「今日、モジュールXのリスクに気づいた人はいるか？」
*マスターのスキル*: 「安全第一」の文化を築くことで、設計段階でのミスを50%削減できます。
