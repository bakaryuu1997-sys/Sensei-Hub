# 🪝 1. THE HOOK: 盗まれた恋文と、現代のエニグマ

第二次世界大戦中、ドイツ軍は極秘命令を暗号化するために **エニグマ (Enigma)** という暗号機を使用しました。それを解読した者が勝利への鍵を握りました。今日、あなたが銀行のウェブサイトにアクセスしたり、メッセージを送ったりするたび、あなたは何十億倍も強力なデジタル版「エニグマ」を使用しています。

もしあなたがパスワードを **平文 (Plaintext)** のまま送信すれば、素人ハッカーでも簡単にそれを読み取ることができます。しかし、もしそれを暗号化すれば、世界で最も強力なスーパーコンピュータでさえ、解読するのに何十億年もかかるでしょう。

Day 53へようこそ。今日は、情報を「封印」する方法を学びます。なぜ HTTPS が安全なのか、なぜ **デジタル署名 (Digital Signature)** は偽造できないのか、そして **PKI (公開鍵基盤)** がどのようにして世界中のインターネットの「守護神」となったのかを理解しましょう。これは **FE試験 (IPA)** に合格するための不可欠な知識であり、開発やシステム設計におけるセキュリティ問題の極めて重要な基盤です。

# 🎭 2. ANALOGY: 「箱」と「2つの鍵」

暗号学は、貴重品を郵便局で送ることに似ています。

1.  **共通鍵暗号 (Symmetric Encryption)**: あなたは荷物を箱に入れ、たった一つの鍵でロックします。あなたはその鍵を、どうにかして相手に秘密裏に送らなければなりません。もし泥棒が鍵を盗めば、箱は開けられてしまいます。
2.  **公開鍵暗号 (Asymmetric Encryption)**:
    - 2つの鍵があります。箱をロックするための **「公開鍵 (Public Key)」** と、箱を開けるための **「秘密鍵 (Private Key)」** です。
    - あなたは「公開鍵」を誰にでも配ります。あなたに何かを送りたい人は、その公開鍵を使って箱をロックします。しかし、その箱を開けることができるのは、秘密鍵を持っている「あなた一人だけ」です。
3.  **ハッシュ関数 (Hash Function)**: 荷物をすりつぶして、特有の形をした「砂の山」にするようなものです。砂から荷物を復元することはできませんが、荷物がわずかでも変われば、砂の山の形は全く変わってしまいます。これが「デジタルの指紋」です。

# ⚙️ 3. UNDER THE HOOD: 古典的な暗号アルゴリズム

**FE Master (IPA)** 試験では、以下の明確な区別が求められます。

### 3.1 共通鍵暗号方式 (Common Key Cryptosystem)
- **仕組み**: 暗号化と復号に同じ1つの鍵を使用します。
- **長所**: 処理速度が極めて速い。
- **短所**: **「鍵の配送問題」** があります。n人が通信する場合、 `n(n-1)/2` 個の鍵を管理しなければなりません。
- **標準**: **AES (Advanced Encryption Standard)**。

### 3.2 公開鍵暗号方式 (Public Key Cryptosystem)
- **仕組み**: ペアとなる2つの鍵（公開鍵と秘密鍵）を使用します。
- **長所**: 鍵の配送問題を解決します。n人に対して、n個の秘密鍵を管理するだけで済みます。
- **短所**: 共通鍵暗号よりも数百倍遅いです。
- **標準**: **RSA** （巨大な素因数分解の困難さを利用）。

### 3.3 ハイブリッド暗号方式 (Hybrid Cryptosystem)
- **仕組み**: 公開鍵暗号を使って「セッション鍵（共通鍵）」を交換し、その後の実際のデータ通信には高速な共通鍵暗号を使用します。これが **SSL/TLS (HTTPS)** の動作原理です。

# 🚀 4. DEEP DIVE: デジタル署名とハッシュ

メッセージが途中で改ざんされていないことを、どうやって知るのでしょうか？

### 4.1 ハッシュ関数 (Hash Function)
- 特徴: **「一方通行性」** （逆算不可）と **「衝突耐性」** （異なるデータから同じハッシュ値が出にくい）。
- 標準: **SHA-256**。

### 4.2 デジタル署名 (Digital Signature)
通常の暗号化とは「逆」の手順を踏みます。
1. 送信者は、メッセージのハッシュ値を自分の **「秘密鍵」** で暗号化します。
2. 受信者は、送信者の **「公開鍵」** でそれを復号します。
- **得られる効果**:
    - **認証 (Authentication)**: 送信者の身元を確認。
    - **否認防止 (Non-repudiation)**: 送信者が「送っていない」と言い逃れできない。
    - **完全性 (Integrity)**: 内容が改ざんされていないことを保証。

# 🏛 *MASTER KNOWLEDGE*: PKI と 電子証明書

この公開鍵が、偽物のハッカーではなく「Google」のものであると、どうして信じられるのでしょうか？

### 5.1 認証局 (CA - Certificate Authority)
公開鍵の持ち主の身元を保証する、信頼できる機関（Let's Encrypt や DigiCert など）です。

### 5.2 X.509 証明書
ウェブサイトの「身分証明書」です。公開鍵と、CAのデジタル署名が含まれています。ブラウザに緑の鍵マークが表示されるとき、あなたのコンピュータはCAの署名を検証し、その公開鍵を信頼しているのです。

# 📍 8. MASTER CASE STUDY: MD5 と SHA-1 の終焉

かつて MD5 や SHA-1 は「王様」でした。しかし：
- 2004年、 **MD5** の衝突（同じハッシュ値を持つ異なるデータ）が数時間で生成できることが証明されました。
- 2017年、Googleは "SHAttered" を発表し、同じ **SHA-1** ハッシュを持つ2つの異なるPDFファイルを作成することに成功しました。
- *マスターの教訓*: セキュリティにおいて永遠はありません。完全に突破される前に、常に強力なアルゴリズム（ **SHA-256** や **SHA-3** ）へアップデートし続けなければなりません。

# 🎯 9. EXAM LOGIC: IPA 試験の「罠」

IPA試験では、 **「誰がどの鍵を持つか」** でよく受験者を混乱させます。
- 機密性のための暗号化： **受信者の公開鍵** を使用。
- 認証のための署名： **送信者の秘密鍵** を使用。
- 署名の検証： **送信者の公開鍵** を使用。

**サンプル問題（日本語）**:
「受信者が送信者のデジタル署名を検証するために使用する鍵はどれか。」
- **正解**: 送信者の公開鍵。

# 💼 10. PROFESSIONAL CONTEXT: 日本企業の「信頼性」へのこだわり

日本の企業は **「信頼性」** を何よりも重視します。データ漏洩は単なる技術的なミスではなく、会社の「誇り」の崩壊を意味します。暗号化を深く理解することは、 **Pマーク (PrivacyMark)** や **ISMS (ISO 27001)** 規格に適合するシステムを設計するために不可欠です。これらは、日本政府や大手企業と仕事をするための「ビザ」のようなものです。
