# 🪝 1. 導入：マイナンバーカード検索システム (マイナンバー)

日本において、**マイナンバー**制度は1億2,500万人以上の国民のアイデンティティを管理しています。役所の職員があなたの12桁の個人番号を入力すると、情報は **一瞬** で表示されます。
-   **線形探索を使った場合**: 1億2,500万回の比較（数秒かかる。遅すぎる）。
-   **二分探索を使った場合**: 約27回の比較（数ミリ秒。良い）。
-   **ハッシュ法を使った実態**: 正確に **1回の計算** （ほぼ0ms）。

データが1億2,500万件あろうが10億件あろうが、検索スピードが変わらないのはなぜでしょうか？それが **ハッシュ法 (Hashing)** の力です。

# 🎭 2. 例え話：アルファベット別の郵便受け

あなたが東京のタワーマンションの管理人だと想像してください。すべての郵便物を一つの大きな山に積み上げる代わりに、AからZまでのラベルが付いた郵便受けに分けます。
-   「田中 (Tanaka)」さんへの手紙があれば、あなたは迷わず「T」の箱へ直行します。
-   **ハッシュ関数** とは、「名前の最初の文字を郵便受けのインデックスにする」というルールのことです。
-   **衝突 (Collision / 衝突)**: 「田中 (Tanaka)」さんと「高橋 (Takahashi)」さんの両方の手紙が届いたとき、両方は同じ箱に入ります。これをどう処理するか？（これがFE試験の重要なポイントです）。

# ⚙️ 3. 詳細解説：ハッシュテーブルの構造

### 3.1 ハッシュ関数
**キー** （入力データ）を、配列の範囲内の **インデックス** （整数）に変換する数学的な関数です。
-   **一般的な公式（除算代入法）**: `インデックス = キー % テーブルサイズ`。

### 3.2 ハッシュテーブル
`Table[Hash(Key)]` という形でデータが格納される配列のことです。

### 3.3 計算量：$O(1)$ の天国
理想的な条件下では、検索、挿入、削除のすべてが **$O(1)$** です。これはコンピュータサイエンスにおいて到達可能な最小の計算量です。

# 🎯 6. 試験対策：衝突の罠

### 6.1 チェイン法 (Chaining)
配列の各スロットに連結リスト（Linked List）を使用します。
-   **長所**: RAMがある限り、データが溢れることがない。
-   **短所**: ハッシュ関数が悪いと、一つの長い連結リストになってしまい、性能が $O(n)$ に低下する。

### 6.2 オープンアドレス法 (Open Addressing)
スロットが埋まっている場合、別の場所を探します。
-   **線形探索法**: `pos + 1, pos + 2...` と順に確認する。
-   **再ハッシュ法**: 2番目のハッシュ関数を使用する。

**頻出問題**: 「**負荷率 (Load Factor)** とは何か？」 これは `要素数 / テーブルサイズ` の比率です。負荷率が 0.7 を超えると、ハッシュテーブルの性能は急激に低下し始めます。

# 💼 7. 実務の文脈：日本のエンジニアがハッシュ法を好む理由

**サントリー** や **トヨタ** のプロジェクトにおいて、 **NestJS** や **Python** を使用したバックエンドシステムでは、ハッシュテーブルは至る所で見られます。
-   **データベースのインデックス**: マイナンバーのようにレコードを高速に見つけるため。
-   **キャッシング**: 重い計算結果を `Map` （ハッシュテーブルの一種）に保存し、次回から即座に取り出すため。
-   **シンボルテーブル**: コンパイラが変数名とメモリ番地を対応付けて管理するため。

もし自分のコードに検索のための多重 `for` ループが多すぎるなら、「ハッシュテーブルを使って $O(1)$ にできないか？」と自問してみてください。

# ⚙️ 7. マスター詳細解説：ハッシュとセキュリティ

日本のIT現場では、「ハッシュ」という言葉が2つの文脈で混同されがちです：**データ構造**（本日学習）と **セキュリティ/暗号**（Day 19 & 71）。先輩の前で恥をかかないよう区別しましょう。

### 7.1 データ構造のためのハッシュ関数
-   **目的**: スピード。速ければ速いほど良い。
-   **性質**: 衝突は許容される（チェイン法などで対処するため）。

### 7.2 暗号学的ハッシュ関数
-   **目的**: 完全性（改ざん検知）と一方向性。
-   **性質**: 衝突は絶対に許されない。入力が1ビット変わるだけで、出力が全く異なるものになる必要がある（**雪崩効果**）。
-   **例**: **SHA-256**（ブロックチェーンやパスワード保存に使用）。SHA-256をハッシュテーブルのインデックスに使うと、計算負荷が高すぎてシステムが非常に遅くなります。

# ❓ 8. Q&A：先輩からの「罠」

**Q: ハッシュテーブルはなぜデータの順序を保持できないのですか？**
*回答*: 格納場所がハッシュ値 (`Key % Size`) に完全に依存するためです。昇順でデータを扱いたい場合は、 **二分探索木** (Day 28) を使用してください。

**Q: ハッシュテーブルが100%埋まったらどうなりますか？**
*回答*: チェイン法なら動き続けますが性能は $O(n)$ に近づきます。オープンアドレス法なら「Table Full」エラーになります。解決策は **動的リサイズ (Dynamic Resizing)** です。70〜80%埋まった時点で、サイズを2倍にした新しい配列を作成し、すべてのデータを移し替えます（**再ハッシュ**）。

**Q: 「完全ハッシュ関数 (Perfect Hash Function)」とは？**
*回答*: 衝突が100%発生しないことが保証された関数のことです。入力されるキーが事前すべて分かっている場合（例：日本の固定の郵便番号リストなど）にのみ作成可能です。

# 📝 9. マスター演習：ロジックの達人

**Q1: 配列サイズ10、ハッシュ関数 $H(K) = K \pmod{10}$。線形探索法で 11, 21, 31 を格納したとき、31 はどこに入りますか？**
- $H(11) = 1 \to$ スロット1。
- $H(21) = 1 \to$ 衝突 $\to$ 次を確認 $\to$ スロット2。
- $H(31) = 1 \to$ 衝突 $\to$ スロット2も埋まっている $\to$ スロット3。
- **回答**: インデックス 3。

**Q2: ハッシュテーブルの最悪時の検索計算量は？**
*回答*: $O(n)$ （すべてのキーが同じインデックスに衝突した場合）。

**Q3: ハッシュテーブルのサイズになぜ素数（Prime Number）がよく使われるのですか？**
*回答*: 周期性を最小限に抑え、剰余計算（%）をした際にデータをより均一に分散させるためです。

**Q4: 「一貫性ハッシュ法 (Consistent Hashing)」の文脈は？**
*回答*: **LINE** のような大規模分散システムで、サーバーの増減時にデータの移動を最小限に抑えるために使われます。
