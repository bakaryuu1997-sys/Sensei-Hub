# 🪝 1. 導入：アマゾン・ジャパン倉庫のトラブル

あなたが**アマゾン・ジャパン**の堺物流センター（FC）のシステムエンジニアだと想像してください。1,000万個の荷物の中から、ある注文品が紛失してしまいました。
-   **方法1（線形探索）**: 作業員を総動員して、倉庫の端から端まで1個ずつ荷物を確認させます。
-   **方法2（二分探索）**: 倉庫はすでにバーコード順に整理されています。あなたは倉庫の中央に立ち、そこのロケーションコードを確認します。関係のない500万個を瞬時に候補から外し、残りの半分で同じことを繰り返します。

プログラミングにおいて、膨大なデータセット（ビッグデータ）に対して誤った探索アルゴリズムを選択すると、日本のクライアントのシステムがダウンし、数十億円規模の損失を招くことになりかねません。

# 🎭 2. 例え話：辞書と数当てゲーム

1.  **線形探索 (Linear Search / 線形探索)**: 整理されていないゲストリストから名前を探すようなものです。上から順番に名前を見ていくしか方法はありません。
2.  **二分探索 (Binary Search / 二分探索)**: 2,000ページの「日越辞典」で「Sushi」を引くようなものです。真ん中のページを開き、それが「M」であれば、「S」は必ず後半にあることがわかります。さらに後半の半分を開き…これを10〜15回繰り返すだけで、目的の単語に辿り着けます。

# ⚙️ 3. 詳細解説：探索の本質

### 3.1 線形探索 - 単純だが確実
このアルゴリズムは、データが整列されている必要がありません。先頭から順に要素を調べ、探している値（**ターゲット**）と比較します。
-   **長所**: あらゆるリスト（配列、連結リスト）で使用可能。
-   **短所**: データ量が多いと非常に遅い ($O(n)$)。

### 3.2 二分探索 - 秩序の力
前提条件：**データがソート（整列）済みであること**。
メカニズム：比較するたびに、残りの要素の半分（50%）を候補から除外します。そのため、計算量が極めて少ないのです：**$O(\log n)$**。

# 💻 5. ロジックと疑似コード：IPA標準

FE試験では、二分探索の疑似コードは穴埋め問題として頻出します。終了条件と `left`, `right` の更新方法に特に注意してください。

**二分探索の疑似コード:**
```text
■ BinarySearch(A[], target)
| 整数型: left, right, mid
| left ← 1
| right ← A.Length
| ▲ while left ≤ right
| | mid ← (left + right) / 2 （整数部分）
| | ▲ if A[mid] = target
| | | return mid
| | ▼ else if A[mid] < target
| | | left ← mid + 1
| | ▼ else
| | | right ← mid - 1
| | ▼
| ▼
| return -1 （見つからない）
```

**IPAの罠**: 実際の実装では、 `(left + right) / 2` を `left + (right - left) / 2` と書くことがよくあります。これは、 `left` と `right` が非常に大きい場合に加算による **整数オーバーフロー (Integer Overflow)** を防ぐためです。マスターエンジニアはこの両方の形式を理解しておく必要があります。

# 🎯 6. 試験対策：最大比較回数

**「生存公式」**: 要素数 $n$ の配列に対する二分探索の最大比較回数は以下の通りです：
$$k = \lceil \log_2(n + 1) \rceil$$

**実際の試験例**:
「要素数が100万個の配列がある。線形探索と二分探索の最大比較回数はそれぞれいくつか？」
-   **線形探索**: 1,000,000回。
-   **二分探索**: $\log_2(1,000,000) \approx 20$回。
=> パフォーマンスに50,000倍の差が生まれます！

# 💼 7. 実務の文脈：リアルタイムシステムでの探索

**楽天** のECプロジェクトにおいて、配送費計算のための郵便番号 (Postcode) 検索は、RAM上にロードされた配列に対して二分探索で行われます。
-   **なぜDBを使わないのか？**: DBへのクエリは数ミリ秒かかります。RAM内の二分探索は数マイクロ秒で終わります。
-   **なぜ全件検索しないのか？**: CPUリソースの無駄遣いだからです。

日本の **システムエンジニア (SE)** は、常に「このデータは固定か？事前ソート可能か？」を問い、線形探索の代わりに二分探索を適用できないか検討します。

# ⚙️ 7. マスター詳細解説：$O(\log n)$ でも足りないとき

### 7.1 補間探索 (Interpolation Search) - 「辞書」の思考
常に真ん中で分けるのではなく、ターゲットの値に基づいて位置を予測します。
-   **例**: A〜Zのリストで「阿部 (Abe)」さんを探すなら、真ん中（M付近）ではなく、最初の方をめくるはずです。
-   **公式**:
$$mid = left + \frac{(target - A[left]) \times (right - left)}{A[right] - A[left]}$$
-   **効率**: データが均一に分布していれば **$O(\log(\log n))$** に達することがあります。これは「電光石火」の速さです。

### 7.2 階段探索 (Staircase Search)：2次元行列での探索
**任天堂** などの企業において、2Dゲームの衝突判定（Collision Detection）を処理する際、ソートされた行列内での探索が行われます。行と列の両方でソートされた行列であれば、右上隅から開始して「階段」のように進むロジックにより $O(M + N)$ で要素を見つけることができます。

# ❓ 8. Q&A：マスターの知恵

**Q: なぜ連結リストに二分探索を使わないのですか？**
*回答*: これは古典的な「罠」問題です。連結リストがソートされていても、インデックスによる **ランダムアクセス** ($O(1)$) ができないためです。 `A[mid]` を見つけるために先頭から辿る必要があり、結局 $O(n)$ かかってしまいます。

**Q: ソートできないデータで探索するには？**
*回答*: **ハッシュ法** (Day 27) を使って $O(1)$ を目指すか、小規模なら線形探索を受け入れます。

**Q: 二分探索で最も多い「無限ループ」の原因は？**
*回答*: `mid + 1` や `mid - 1` を忘れることです。単に `left = mid` とすると、要素が2つ残っていてターゲットが右側にある場合、ループが終了しなくなります。

# 📝 9. マスター演習：ロジックの達人

**Q1: 配列 $A = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]$ で Target = 23 を二分探索で探してください。**
*トレース*:
1. `left=1, right=10, mid=5, A[5]=16`。 $16 < 23 \to left = 6$。
2. `left=6, right=10, mid=8, A[8]=56`。 $56 > 23 \to right = 7$。
3. `left=6, right=7, mid=6, A[6]=23`。 **発見！**

**Q2: 二分探索が「分割統治法」と呼ばれるのはなぜ？**
*回答*: 大きな問題（n個から探す）を、半分（n/2個から探す）という小さな問題に分解し続けるからです。

**Q3: 40億件のレコードがあるシステムで、二分探索の最大比較回数は？**
*回答*: $2^{32} \approx 42$億なので、最大でも32回です。

**Q4: 線形探索を優先すべきケースは？**
*回答*: 1. 配列が極めて小さい（10要素未満）場合。 2. データが頻繁に入れ替わり、ソートのオーバーヘッドが探索時間を上回る場合。

**Q5: IPA疑似言語の `▲` と `▼` は何を表しますか？**
*回答*: ブロック（ループや条件文）の開始と終了を表します（C/Javaの `{ }` に相当）。

**Q6: `left + (right - left) / 2` が安全な理由は？**
*回答*: `left` と `right` が非常に大きな整数の場合に、加算による **整数オーバーフロー** を防げるからです。

**Q7: 反復（ループ）版二分探索の空間計算量は？**
*回答*: $O(1)$。

**Q8: 「番兵 (Sentinel)」を用いた線形探索とは？**
*回答*: 配列の末尾にターゲットと同じ値をあらかじめ置いておく手法です。これにより、ループ内での「範囲チェック (`i < n`)」が不要になり、比較回数を半減できます。

**Q9: ブラウザの `Ctrl + F` で使われているのは？**
*回答*: 文字列探索アルゴリズム（**Boyer-Moore** や **KMP**）です。テキストはソートされていないため、二分探索は使えません。

**Q10: 「平均比較回数 (ASL)」の重要性は？**
*回答*: 日本のSIerプロジェクトでは、SLA（サービス品質保証）で約束したレスポンスタイムを保証するために、このASLを算出して性能を証明します。
