# DevOpsのためのLinux：コマンドラインとシステム権限のマスター 🐧

Day 05へようこそ！過去4日間、私たちは Docker とコンテナを使って高いレイヤを飛び回ってきました。しかし今日は、世界中のサーバーの90%以上にパワーを供給しているオペレーティングシステム、**Linux** (#(Linux)) を理解するために「地上」に降り立ちます。

あなたが実行するすべてのコンテナは、実質的に Linux 上のプロセス（Process）です。将来遭遇するネットワーク、ストレージ、セキュリティのあらゆる問題は、すべて Linux のコア概念にたどり着きます。Docker が「車」なら、Linux はその中にある「エンジン」そのものです。

---

## 🪝 THE HOOK：「Permission Denied」と深夜1時のトラブル

ある夜、あなたのロギングシステムが突然停止しました。コンテナのログを確認すると、真っ赤な一行が表示されています：
`EACCES: permission denied, open '/var/log/app.log'`

あなたはパニックになります。「なぜ？昨日まで普通に動いていたのに！」。あなたはディレクトリ全体に対して `chmod 777` を実行してしまいます（これは極めて危険で、プロフェッショナルとは言えない行為です）。エラーは消えましたが、数日後、その「全開のドア」から侵入したハッカーによってシステムが攻撃されてしまいました。

Linux における **権限（Permissions）** (#(Permissions)) と **プロセス（Processes）** (#(Processes)) に関する知識の欠如は、エンジニアが **Master** レベルに到達するのを阻む最大の壁です。

---

## 🎭 ANALOGY：図書館の塔と利用カード

### 1. ファイルシステム階層：図書館の塔
Linux のファイルシステムは、Windows のように Cドライブや Dドライブに分かれていません。それは一つの **家系図（ルート /）** です。
- **/bin & /usr/bin**: 誰でも使える **仕事道具**（ペンや定規）のようなもの。
- **/etc**: **設定ファイルのキャビネット**。図書館の規則が保管されている場所です。
- **/var**: **保管庫**。ログなどの記録が毎日積み上げられる場所です。
- **/root & /home**: 管理者や職員の **個室**。

### 2. 権限（Permissions）：利用カード
Linux のすべてのファイルには、権限を記した「ラベル」が貼られています：**読み取り (r)**, **書き込み (w)**, **実行 (x)**。
- **Owner** (#(Owner))：ファイルの所有者。
- **Group** (#(Group))：共同作業グループ。
- **Others** (#(Others))：それ以外の全世界の人。

機密性の高い本を持っていると想像してください。自分には読み書き（rw）を許可し、グループには読み取り（r）だけを許可し、部外者には何も見せない（-）ようにします。これが Linux がデータを守る仕組みです。

## ⚙️ UNDER THE HOOD：OSの心臓部

### 1. プロセス管理（Process Management）
実行中のすべてのプログラムは **プロセス** (#(Process)) と呼ばれます。各プロセスには固有の ID（**PID**）が割り振られます。
- `ps aux`: 実行中の全プロセスをリスト表示します。
- `top` または `htop`: システムの「鼓動」（CPU/RAM使用率）を確認します。
- `kill -9 [PID]`: フリーズしたプロセスを「強制終了」させるコマンドです。

### 2. 数値による権限表記（Numeric Permissions）
`755` や `644` という数字が何を意味するのか、疑問に思ったことはありませんか？
- **読み取り (4)**, **書き込み (2)**, **実行 (1)**。
- **7** (4+2+1)：全権限。
- **5** (4+1)：読み取りと実行のみ。
- **4**：読み取りのみ。
つまり `755` は、所有者が全権限（7）を持ち、グループとその他は読み取りと実行（5）のみができることを意味します。

### 3. Bashスクリプト：自動化の神ツール
DevOps エンジニアは、繰り返しの作業を手動で行うことはありません。彼らは **Bashスクリプト** (#(Bash Script)) を書きます。
- **変数（Variables）**: 情報を保存します。
- **パイプ (|)**: あるコマンドの出力を別のコマンドの入力に繋ぎます。例：`ps aux | grep node`（全プロセスの中から node プロセスを探す）。
- **リダイレクト (>)**: 結果をファイルに書き込みます。


## 💻 DEVOPS IN PRACTICE：ログ掃除の自動化

状況：サーバーのディスク容量が、巨大なログファイルのせいで頻繁に一杯になります。7日より古いログファイルを自動的に削除するスクリプトが必要です。

### スクリプト: `cleanup_logs.sh`
```bash
#!/bin/bash

# ログディレクトリのパス
LOG_DIR="/var/log/my-app"

# 7日より古い .log ファイルを探して削除する
# -mtime +7: 最終更新が7日前
find $LOG_DIR -name "*.log" -mtime +7 -exec rm -f {} \;

echo "ログのクリーンアップが完了しました: $(date)" >> /var/log/cleanup.log
```

このスクリプトを毎晩自動で実行するには、Linux の「目覚まし時計」である **Cron Job** (#(Cron Job)) を使用します。

### 面接の質問：「`sudo` と `su` の違いは？」
- **回答**: 
    - `su` (Switch User): ターゲットのアカウント（通常は root）のパスワードを入力し、そのアカウントとして完全にログインします。
    - `sudo` (SuperUser Do): 自分のパスワード（許可されている場合）を使って、root 権限でコマンドを実行します。`sudo` は「誰が何をしたか」がログに残るため、より安全です。
