# Day 20: エンジン内部のコード - ストアドプロシージャと関数 ⚙️

Day 20 へようこそ！ これまで、あなたはデータベースをバックエンドアプリからSQLコマンドを送り込むだけの「ただの箱」として扱ってきたかもしれません。

しかし、シニア・データベース・アーキテクトは、データベースが **「スーパーコンピュータ」** であることを知っています。合計値を計算するためだけに100万行のデータを Node.js サーバーに持ってくる代わりに、ロジックを **データベース内部** で実行して結果だけを受け取る方がはるかに効率的です。

これが、**ユーザー定義関数 (UDF)** と **ストアドプロシージャ** の力です。

4.  **セキュリティ (RPC):** 関数を使用して、API を SQL インジェクションから保護します。

## 🧠 2. 哲学：ロジックをデータに近づける

巨大な倉庫（データベース）があり、あなたのオフィス（バックエンド）が10km離れていると想像してください。

- **アマチュアのやり方：** 倉庫に行き、1,000個の重い箱を車に積み、10km走ってオフィスに戻り、中身を数え、特定の商品を見つけて、残りをまた10km走って返しに行きます。（これがバックエンドでロジックを行う時の姿です）
- **プロのやり方：** 倉庫の **内部** にスタッフを雇います。彼らに電話して「この箱を数えて、数字だけ教えて」と言うだけです。（これがストアド関数の姿です）

```ascii

  +-----------------+           +---------------------+
  |   NODE.JS アプリ | <-------+ |     データベース     |
  |   (オフィス)    |           |    (データの巨大倉庫) |
  +-----------------+           +---------------------+
           |                               |
           |   1. 10万行をクエリ            |
           +-----------------------------> |
           |                               |
           |   2. 100MBのデータを送信       |
           | <-----------------------------+
           |                               |
           |   3. ロジック：集計/フィルタ     |

           |                               |

           | <-----------------------------+
           +-------------------------------+
```

## 💻 3. 実戦 SQL：初めての関数を書く

PostgreSQL では **PL/pgSQL** を使います。VIP顧客の割引額を計算する関数を書いてみましょう。

```sql
-- 数値を返す「関数」を作成
CREATE OR REPLACE FUNCTION calculate_vip_discount(price NUMERIC, vip_level INT)
RETURNS NUMERIC AS $$
DECLARE
    discount_rate NUMERIC;
BEGIN
    -- データベース内部のロジック！
    IF vip_level >= 5 THEN
        discount_rate := 0.20; -- 20% 割引
    ELSE
        discount_rate := 0.05; -- 5% 割引
    END IF;

    RETURN price * (1 - discount_rate);
END;
$$ LANGUAGE plpgsql;

-- クエリ内で使用：
SELECT full_name, calculate_vip_discount(1000, loyalty_points / 100) AS final_price
FROM users;
```

### プロシージャ (銀行振込などの「操作」用)
プロシージャは、特定の値を返すことよりも、何かを **「実行」** すること（例：振込処理など）を主目的とする場合に使います。

```sql
CREATE OR REPLACE PROCEDURE transfer_funds(sender_id INT, receiver_id INT, amount NUMERIC)
AS $$
BEGIN
    -- 複数のSQLコマンドを一つの呼び出しにまとめる
    UPDATE accounts SET balance = balance - amount WHERE id = sender_id;
    UPDATE accounts SET balance = balance + amount WHERE id = receiver_id;
    
    COMMIT; -- プロシージャはトランザクションを制御できます！
END;
$$ LANGUAGE plpgsql;

-- 実行：
CALL transfer_funds(1, 2, 500);
```

## 💡 4. シニアの秘密：RPC と API セキュリティ

**Supabase** を使っている場合、これらの関数を **RPC (Remote Procedure Call)** を使ってフロントエンドから直接呼び出すことができます。

JavaScript で複雑な `SELECT` クエリを書く代わりに（SQLインジェクションのリスクがあります）、ロジックをデータベース関数にカプセル化し、`supabase.rpc('my_function')` を呼び出すだけにします。これにより、ユーザーはテーブル構造を直接見ることができず、関数が許可した結果だけを見ることになります。
