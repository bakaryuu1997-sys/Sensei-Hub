## 3. 本日の内容

### Zero-shot 学習とは

**定義**：AI モデルが、その特定タスクの例を見ずに、直接タスクを実行する学習方法。

（Học Zero-shot: mô hình thực hiện tác vụ mà không cần ví dụ）

```
従来の機械学習：
タスク A：1000 個のデータで学習
→ タスク A を実行

タスク B が出現：
新しく 1000 個のデータで学習
→ タスク B を実行
→ 毎回学習が必要（時間・コスト大）

Zero-shot 学習：
事前学習済み LLM：
→「翻訳」タスク：例なしで実行
→「要約」タスク：例なしで実行
→「感情分析」タスク：例なしで実行
→ 新しい学習が不要
```

（Zero-shot: mô hình không cần ví dụ mới, trực tiếp thực hiện）

### Zero-shot 学習の仕組み

```
【プロンプト】
「これは肯定的か否定的か、感情を分類してください：
『この映画は本当に素晴らしかった』」

【AI の処理】
1. 言語の一般的なパターンを知っている
   （事前学習で学んだ）
2. 「素晴らしかった」= 肯定的
3. 分類を返す

【出力】
「肯定的」

特徴：
・例を示さなくても理解
・事前学習で一般的な言語知識がある
・タスク説明のみで対応
```

### Few-shot 学習とは

**定義**：AI モデルが、少数の例を見ることで、タスクを学習・実行する方法。

（Học Few-shot: mô hình học từ vài ví dụ）

```
【プロンプト】
「以下の例に従って、新しい文の感情を分類してください。

例 1：「このレストランは最高」→ 肯定的
例 2：「サービスがひどい」→ 否定的
例 3：「普通です」→ 中立

新しい文：『商品は期待通りでした』」

【AI の処理】
1. 例からパターンを抽出
   「最高」「ひどい」の言葉が分類を決める
2. 新しい文「期待通り」を分析
3. 分類を返す

【出力】
「肯定的」（期待通り = ポジティブ）
```

（In-context learning: AI học từ các ví dụ trong prompt）

### Zero-shot vs Few-shot

| 項目 | Zero-shot | Few-shot |
|------|-----------|----------|
| 必要な例数 | 0 個 | 2～5 個程度 |
| セットアップ時間 | 短い | 少し長い |
| 精度 | 基本的 | より高い |
| 汎化性 | 高い | 中程度 |
| 計算量 | 少ない | 少し多い |
| ユースケース | 単純タスク | 複雑・特定タスク |

## 4. 具体例

### 例1：感情分析

**Zero-shot：**
```
プロンプト：
「次のテキストの感情を「肯定的」「否定的」「中立」で分類してください：
『昨日買った本は面白かった』」

応答：
「肯定的」

理由：
・「面白かった」= ポジティブ
・事前学習で言語知識がある
・例なしでも理解
```

**Few-shot：**
```
プロンプト：
「以下の例に従って感情を分類してください：

例 1：『このコーヒーは美味しい』→ 肯定的
例 2：『駅は混んでいる』→ 中立
例 3：『サービスは最悪です』→ 否定的

新しいテキスト：『昨日買った本は面白かった』」

応答：
「肯定的」

利点：
・分類基準がより明確
・より正確な応答
```

### 例2：翻訳

**Zero-shot：**
```
プロンプト：
「日本語を英語に翻訳してください：
『おはようございます』」

応答：
「Good morning」

理由：
・基本的な表現は事前学習で学習済み
・言語パターンを知っている
```

**Few-shot：**
```
プロンプト：
「以下のパターンに従って翻訳してください：

例 1：『こんにちは』→『Hello』
例 2：『ありがとう』→『Thank you』
例 3：『申し訳ありません』→『I am sorry』

翻訳：『おはようございます』」

応答：
「Good morning」

利点：
・より自然で文脈に合った翻訳
・特定のスタイル（敬語など）を指定できる
```

### 例3：テキスト分類

**Zero-shot：**
```
プロンプト：
「次のメールがスパムか正当なメールか分類してください：
『あなたは 100 万円を獲得しました！ここをクリック』」

応答：
「スパム」

理由：
・スパムメールの典型的な特徴を知っている
・怪しい表現を認識
```

**Few-shot：**
```
プロンプト：
「以下の例に従ってメールを分類してください：

例 1：『重要な会議は明日 10 時です』→ 正当
例 2：『クリックして今すぐ稼ぐ！』→ スパム
例 3：『請求書を確認してください』→ 正当

新しいメール：『あなたは 100 万円を獲得しました！ここをクリック』」

応答：
「スパム」

利点：
・企業特有のメール形式を学べる
・誤分類を減らせる
```

### 例4：プログラミング

**Zero-shot：**
```
プロンプト：
「Python で、リストの最大値を取得する関数を書いてください」

応答：
def max_value(lst):
    return max(lst)

理由：
・基本的な Python 関数は知られている
・`max()` 関数の使い方を知っている
```

**Few-shot：**
```
プロンプト：
「以下のスタイルに従って関数を書いてください：

例 1：
# 合計を計算
def sum_list(lst):
    total = 0
    for num in lst:
        total += num
    return total

例 2：
# 平均を計算
def avg_list(lst):
    return sum(lst) / len(lst)

# リストの最大値を取得
def max_value(lst):」

応答：
    max_val = lst[0]
    for num in lst:
        if num > max_val:
            max_val = num
    return max_val

理由：
・ビルトイン関数を避け、ループで実装
・コメント形式を模倣
→ より教育的で初心者向き
```

## 5. In-context 学習（プロンプト内学習）

**定義**：プロンプト内に例を示すことで、AI がその場で学習する現象。

```
重要なポイント：
・AI のパラメーターは変わらない
・「プロンプト内のコンテキストから」パターンを認識
・毎回のプロンプトで異なる「学習」が可能

例：
プロンプト 1：「英語の文法を教える」→ 教育的な応答
プロンプト 2：「ジョークを作って」→ ユーモア満載の応答
同じ AI でも、プロンプトで「学習」内容が変わる

これが「In-context 学習」
→ プロンプトエンジニアリングの基礎
```

## 6. Zero-shot vs Few-shot 使い分け

| 状況 | 推奨 |
|------|------|
| 標準的なタスク（翻訳、要約など） | Zero-shot |
| 特定の形式や スタイルが必要 | Few-shot |
| タスクが複雑・曖昧 | Few-shot |
| 速度が重要 | Zero-shot |
| 精度が重要 | Few-shot |
| プロンプトは短くしたい | Zero-shot |

## 7. 試験で出やすいポイント

1. **Zero-shot の定義**

2. **Few-shot の定義**
   - 少数の例からタスク学習

3. **In-context 学習**
   - プロンプト内のコンテキストから学習

4. **使い分け**
   - タスクの複雑さによる選択

5. **生成AI での活用**
   - プロンプトエンジニアリングの基礎

## 8. 間違えやすいポイント

❌ **間違い1**: 「Few-shot = 少し学習」
✅ **正解**: Few-shot は「プロンプト内で例を示す」こと

❌ **間違い2**: 「Zero-shot = 常に失敗」
✅ **正解**: 基本的なタスクなら十分に機能

❌ **間違い3**: 「Few-shot = AI の重みを更新」
✅ **正解**: プロンプト内学習、パラメーター不変

❌ **間違い4**: 「例が多いほどいい」
✅ **正解**: 2～5 個程度で十分、多すぎるとプロンプトが長くなり効率低下

❌ **間違い5**: 「In-context 学習 = 永続的」
✅ **正解**: 次のプロンプトでは学習内容が失われる

## 9. 確認問題

### 問題1
Zero-shot の説明として正しいものはどれですか？

A) 継続学習をしない
B) タスクの例を見ずに直接実行
C) 失敗を否定する
D) 過学習だけを避けようとする

**答え**: B

**解説**: Zero-shot は「ゼロ個の新規例」で、事前知識から直接タスク実行します。

---

### 問題2
Few-shot の説明として正しいものはどれですか？

A) 目的を明確にしない
B) 少数の例を見てから実行
C) AI の重みを大きく更新
D) 課題を伝えない

**答え**: B

**解説**: Few-shot は「少数の例」（通常 2～5 個）を見て、パターンを理解してから実行します。

---

### 問題3
In-context 学習の説明として正しいものはどれですか？

A) プロンプト内のコンテキストから、その場で学習
B) 条件を変えずに行う
C) 一度だけ行って終わる
D) テストデータを学習に使う

**答え**: A

**解説**: In-context 学習では、AI のパラメーターは変わらず、プロンプト内の情報から学習します。

---

### 問題4
次のうち正しいものはどれですか？

A) 常に Few-shot
B) 改善点を含めない
C) 常に Zero-shot
D) タスクによる（複雑なら Few-shot）

**答え**: D

**解説**: 基本的なタスクなら Zero-shot で十分、複雑なら Few-shot で精度向上。

---

### 問題5
次のうち正しいものはどれですか？

A) 例から期待される形式やパターンが明確になる
B) 利用者を無視する
C) AI の能力が上がるから
D) 透明性を欠く

**答え**: A

**解説**: 例により、分類基準や出力形式が明確になり、AI が期待を理解します。

---

### 問題6
次のうち正しいものはどれですか？

A) AI のパラメーターが変わる
B) 公平性を無視する
C) プロンプト内の情報のみで、一時的に「学習」
D) 利用者を無視する

**答え**: C

**解説**: 次のプロンプトでは学習が失われ、新しいプロンプトで新しく「学習」します。

---

### 問題7
次のうち正しいものはどれですか？

A) 目的を明確にしない
B) 事前学習で基本的な言語パターンを学んでいる
C) 対象を限定しすぎる
D) 偏りを放置する

**答え**: B

**解説**: LLM は大規模テキストから言語パターンを学んでいるため、基本的な翻訳は例なしでできます。

---

### 問題8
次のうち正しいものはどれですか？

A) 公平性を無視する
B) 改善点を含めない
C) 専門用語をそのまま使う
D) 2～5 個程度

**答え**: D

**解説**: 多すぎるとプロンプトが長くなり効率低下、少なすぎるとパターン不明確。

---

### 問題9
以下のどちらが効果的？

A)「テキストを分類して」（Zero-shot）
B)「以下の例に従い分類してください：【3 個の例】。新しいテキスト：...」（Few-shot）

**答え**: B（複雑なタスクの場合）  
**解説**: 分類基準が明確なら Few-shot の方が正確です。

---


### 問題10
次のうち正しいものはどれですか？

A) 新しい知識を避ける
B) プロンプト内の例から、その場で形式を学ぶ
C) プログラミング言語の学習
