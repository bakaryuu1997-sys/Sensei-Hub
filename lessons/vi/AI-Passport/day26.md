## 3. 本日の内容

### プロンプトエンジニアリングとは

**定義**：生成AI（特に LLM）から、期待通りの高品質な応答を引き出すための指示の書き方。

（Kỹ thuật xây dựng lời nhắc: viết chỉ thị để AI tạo ra đáp ứng tốt nhất）

```
類似：
人間に仕事を指示する場合、詳細に指示しないと、
予期しない結果になることがある

AI も同じ：
不明確な指示 → 不正確・不適切な応答
明確な指示 → 高品質な応答
```

### プロンプトの基本要素

#### 1. 明確さ（Clarity）

```
❌ 悪い例：
「何か説明して」

✅ 良い例：
「太陽系の惑星について、初心者向けに 300 字で説明してください」

理由：
・何を説明するのか明確
・対象読者が明確
・長さが指定
→ 正確な応答
```

#### 2. 具体性（Specificity）

```
❌ 悪い例：
「プログラミングについて教えて」

✅ 良い例：
「Python で、ユーザーが入力した数が偶数か奇数かを判定する
プログラムの書き方を、初心者向けに教えてください」

理由：
・使用言語が明確
・具体的な目的が明確
・技術レベルが明確
→ 最適な応答
```

#### 3. コンテキスト

```
❌ 悪い例：
「新製品についてのメールを書いて」

✅ 良い例：
「新型スマートフォンを発表するビジネスメール
対象：既存顧客
トーン：専門的だがアクセスしやすい
含めるべき内容：価格、主な機能、発売日」

理由：
・対象が明確
・含めるべき情報が明確
・トーンが明確
→ 用途に合ったメール
```

#### 4. 制約条件

```
❌ 悪い例：
「説明して」

✅ 良い例：
「AI の 3 つの主な分野を、
各 50 字以内で説明してください」

理由：
・何が3つなのか明確
・文字数制限がある
→ 簡潔で読みやすい応答
```

### プロンプトのテクニック

#### テクニック1：段階的指示（Step-by-step）

```
プロンプト：
「以下の問題を解いてください。解く過程も示してください。

問題：100 から 1 ずつ引いていくと、10 で割り切れる最初の数は何か？

解く手順：
1. 最初の条件を理解
2. 条件を満たす数を探す
3. 確認
4. 答え」

応答：
「1. 100 から 1 ずつ引く: 100, 99, 98, 97...
2. 10 で割り切れる: 100, 90, 80...
3. 最初のもの: 100（すでに 10 の倍数）
答え: 100」

利点：
・複雑な問題も解きやすい
・推論過程が見える
・エラーチェックできる
```

#### テクニック2：例の提示（Few-shot Learning）

```
プロンプト：
「以下の翻訳パターンに従って、最後の文を翻訳してください。

例:
日本語：彼は医者です。
英語：He is a doctor.

日本語：彼女は学生です。
英語：She is a student.

日本語：私はエンジニアです。
英語：」

応答：「I am an engineer.」

利点：
・AI が期待される形式を理解
・ゼロから考えるより正確
```

#### テクニック3：ロール設定

```
プロンプト：
「あなたは、50 年の経験を持つコンピュータサイエンスの教授です。
初心者向けに、アルゴリズムについて、
親しみやすく、実例を交えて説明してください。」

応答：
「アルゴリズムは、問題を解くための『レシピ』のようなものです。
料理のレシピが『材料 → 手順 → 完成』という流れなら、
アルゴリズムも『入力 → 処理 → 出力』という流れです。

例えば...」

利点：
・AI がトーンやスタイルを調整
・専門的だが分かりやすい応答
```

#### テクニック4：制約の明示

```
プロンプト：
「次のルールに従って答えてください：
1. 2 文以内
2. 日本語で回答
3. 技術用語を避ける
4. 初心者が理解できる表現

質問：AI とは何ですか？」

応答：
「AI とは、コンピュータが人間のようにやることを学ぶ技術です。
例えば、メールが迷惑かどうかを自動判定するのは AI の一種です。」

利点：
・出力形式が統一
・不要な情報がない
・読みやすい
```

#### テクニック5：システムプロンプト

```
【ユーザープロンプト】
「AI について説明して」

【システムプロンプト設定】
「あなたは親切で知識豊富なアシスタントです。
難しい内容をシンプルに説明してください。
常に例を含めてください。
不明な点があれば質問を促してください。」

結果：
AI + システムプロンプト
→ より親切で例が豊富な応答

利点：
・全ての会話で一貫した振る舞い
・設定を毎回書く必要がない
```

## 4. 具体例

### 例1：ビジネスメール作成

```
❌ 不効果的なプロンプト：
「メール を書いてください」

✅ 効果的なプロンプト：
「以下の条件に従って、新しいプロジェクトの提案メールを作成してください。

対象：上司
目的：新規プロジェクトの承認を得る
トーン：プロフェッショナルだが親しみやすい
含めるべき内容：
- 背景（なぜこのプロジェクトが必要か）
- 目的（どんな価値があるか）
- 実行計画（いつ、誰が、どのように）
- 必要なリソース（予算、人員など）
- 期待される成果

文字数：300～400 字」

結果：
構成がしっかりしていて、上司に納得してもらいやすいメール
```

### 例2：プログラミング問題

```
❌ 不効果的なプロンプト：
「Python でリスト を処理するコードを書いて」

✅ 効果的なプロンプト：
「Python で、以下の要件を満たすコードを書いてください。

要件：
1. [1, 3, 2, 5, 4] というリストを受け取る
2. 偶数のみを抽出
3. 大きい順にソート
4. 結果を print

出力例：
[4, 2]

初心者向けのコメント付きで、わかりやすく書いてください。」

結果：
明確で再利用可能な、初心者向けコード
```

### 例3：コンテンツ作成

```
❌ 不効果的なプロンプト：
「記事を書いて」

✅ 効果的なプロンプト：
「以下の内容に関する日本語ブログ記事を作成してください。

タイトル：「初心者のための AI 入門」
対象読者：技術背景のない一般人
文字数：1000～1200 字
構成：
1. 導入（AI とは何か簡潔に）
2. AI の 3 つの応用例
3. AI の可能性と課題
4. 結論

トーン：親しみやすいが情報量が多い
含めるべきもの：初心者が理解できる比喩や例」

結果：
構造的で読みやすく、対象読者に合ったブログ記事
```

## 5. 試験で出やすいポイント

1. **プロンプトエンジニアリングの定義**
   - 効果的なプロンプトを設計する技術

2. **基本要素**
   - 明確さ、具体性、コンテキスト、制約条件

3. **テクニック**
   - 段階的指示、例の提示、ロール設定、制約の明示

4. **システムプロンプト**
   - モデルの基本的な振る舞いを指定

5. **効果**
   - 高品質な応答を引き出せる

---

## 6. 間違えやすいポイント

❌ **間違い1**: 「プロンプトエンジニアリング = 複雑なテクニック」
✅ **正解**: 基本は「明確で具体的に書く」こと

❌ **間違い2**: 「プロンプト = 短いほどいい」
✅ **正解**: 必要な情報があれば詳細に書くべき

❌ **間違い3**: 「プロンプトエンジニアリング = 常に必要」
✅ **正解**: 簡単な質問なら不要、複雑な場合に有効

❌ **間違い4**: 「AI は どんなプロンプトでも理解」
✅ **正解**: 不明確なプロンプトは誤解を招く

❌ **間違い5**: 「プロンプトエンジニアリング = 新しいスキル」
✅ **正解**: 基本は「人間に指示を与える」のと同じ

## 7. 確認問題

### 問題1
プロンプトエンジニアリングの定義として正しいものはどれですか？

A) 生成AI から期待通りの応答を引き出す指示の書き方
B) プログラミング言語の一種
C) 偏りを放置する
D) 偏ったデータで学習する

**答え**: A


**解説**: 効果的なプロンプト設計により、AI から最高品質の応答を得られます。

---

### 問題2
高品質なプロンプトに含まれる要素として正しいものはどれですか？

A) 偏りを放置する
B) 明確さ、具体性、コンテキスト、制約条件
C) 新しい知識を避ける
D) 偏った対象だけを重視する

**答え**: B


**解説**: これら 4 つの要素を備えたプロンプトが、高品質な応答を生み出します。

---

### 問題3
段階的指示を使う利点として正しいものはどれですか？

A) 表示だけを変える
B) AI の処理が速くなる
C) 複雑な問題も AI が段階的に解く → エラーが少ない
D) 障害に備えない

**答え**: C


**解説**: 複雑な問題も、段階に分けることで、より正確に解けます。

---

### 問題4
次のうち正しいものはどれですか？

A) 性能よりも速度だけを重視する
B) AI が期待される形式を理解 → より正確な応答
C) 説明性を無視する
D) 効果を証明しない

**答え**: B


**解説**: 例を示すことで、AI はパターンを理解し、同様の形式で応答します。

---

### 問題5
次のうち正しいものはどれですか？

A) 関係者を無視する
B) AI がそのロールに応じた専門的で親しみやすい応答
C) 効果を測定しない
D) 偏ったデータで学習する

**答え**: B


**解説**: 「50 年の経験を持つ教授」などと設定すれば、その視点から応答します。

---

### 問題6
次のうち正しいものはどれですか？

A) 利用者の声を無視する
B) コンピュータシステムの設定
C) モデルの基本的な振る舞いを指定 → 全ての会話で有効
D) ユーザーからのプロンプト

**答え**: C


**解説**: システムプロンプトを設定すれば、毎回ロール設定を書かずに済みます。

---

### 問題7
次のうち正しいものはどれですか？

A) 利用者の声を無視する
B) 専門用語をそのまま使う
C) 説明責任を無視する
D) 出力形式が統一 → 読みやすく予測可能

**答え**: D


**解説**: 「2 文以内」「300 字」など制約を指定すれば、出力が統一されます。

---

### 問題8
以下のプロンプトはどちらが効果的？

A)「AI について説明して」
B)「AI とは何か、初心者向けに 150 字で、例を 1 つ含めて説明してください」

**答え**: B  
**解説**: 具体的で、対象読者、長さ、含めるべき要素が明確です。

---



### 問題9
次のうち正しいものはどれですか？

A) 同じ AI でも、プロンプト次第で応答の品質が大きく変わる
B) 十分に検証しない
C) AI の能力を引き出す唯一の方法
D) 複雑なテクニックを学ぶ必要があるから

**答え**: A


**解説**: 明確で具体的なプロンプト → 高品質な応答

---

### 問題10
次のうち正しいものはどれですか？

A) 使いにくい操作を設計する
B) プロンプトを一度書いておしまい
C) プロンプトを試す → 応答を評価 → 改善 → 繰り返し（反復改善）
D) 個人情報を無断で利用する

**答え**: C


**解説**: 最初のプロンプトが完璧でなくても、改善を繰り返すことで最適化できます。

## 8. 今日のまとめ

**プロンプトエンジニアリング**は、効果的なプロンプト設計の技術です。

**基本要素**：明確さ、具体性、コンテキスト、制約条件

**テクニック**：段階的指示、例の提示、ロール設定、制約の明示

**効果**：同じ AI でも、プロンプト次第で応答の品質が変わる

**プロセス**：試す → 評価 → 改善 → 繰り返し
