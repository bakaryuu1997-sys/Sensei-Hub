## 3. 本日の内容

### RAG とは

**定義**：生成AI に外部知識ベース（データベース）を統合し、その知識に基づいて回答を生成する技術。

（RAG: tích hợp AI với cơ sở dữ liệu để tạo sinh dựa trên kiến thức ngoài）

```
従来の LLM：
ユーザー質問
    ↓
LLM（事前学習データのみで処理）
    ↓
ハルシネーション リスク有

RAG：
ユーザー質問
    ↓
外部知識ベースから関連情報を検索
    ↓
LLM（検索結果 + 質問で処理）
    ↓
根拠あるファクト ベースの回答
    ↓
ハルシネーション リスク削減
```

---

### RAG の仕組み

```
【ステップ 1：質問をベクトル化】
ユーザー質問：「2024 年の日本の失業率は？」
    ↓
質問をベクトル表現に変換
「質問」→ [0.1, -0.3, 0.5, ...]

【ステップ 2：ベクトルデータベースから検索】
質問ベクトルと類似のドキュメントを検索
    ↓
統計データベース内の 2024 年失業率データを取得
「日本の 2024 年失業率は 2.4% です」

【ステップ 3：LLM に文脈を提供】
LLM への入力：
「以下の情報を使用して回答してください：
【外部知識】日本の 2024 年失業率は 2.4%

質問：2024 年の日本の失業率は？」

【ステップ 4：LLM が回答を生成】
LLM（根拠ある情報に基づいて）：
「外部知識によると、2024 年の日本の失業率は 2.4% です」

【ステップ 5：出典を提示】
回答に出典を付記
「失業率は 2.4% です。（出典：日本統計局）」
```

### ベクトルデータベース

**仕組み**：
```
通常のデータベース：
「キーワード」→「情報」（キーマッチング）
不正確な場合がある

ベクトルデータベース：
テキスト → 埋め込み（Embedding）→ ベクトル
例：「失業率」 → [0.2, 0.5, -0.1, ...]

質問「失業」のベクトルと
ドキュメント「失業率」のベクトルの
「距離」を計算
    ↓
近いもの = 関連性高

利点：
・セマンティック（意味的）に類似した情報を検索
・キーワード完全一致に依存しない
・類義語や曖昧な質問にも対応
```

### RAG の利点

#### 1. ハルシネーション 削減

```
従来の LLM：
「その本について何か知ってる？」
AI：「ああ、その本は著者の最高傑作です...」
（ハルシネーション の可能性）

RAG 版：
「その本について何か知ってる？」
検索：データベースに「その本」が存在しない
LLM：「申し訳ありませんが、その本の情報が見つかりません」
（正直な回答）
```

#### 2. 最新情報への対応

```
従来の LLM（知識カットオフ：2023 年 4 月）：
「2024 年のニュース」
AI：「2024 年のデータはありません」

RAG 版（リアルタイムデータベース接続）：
「2024 年のニュース」
検索：最新ニュースデータベースから 2024 年情報を取得
LLM：「2024 年のニュースは...」
（最新情報に対応）
```

#### 3. 企業固有の知識

```
企業 A のドキュメント：
・社内ポリシー
・製品情報
・顧客データ

RAG ベース AI：
ユーザー：「弊社の返品ポリシーは？」
検索：社内ドキュメントから返品ポリシーを取得
LLM：「貴社のポリシーによると...」

従来の LLM：
「一般的な返品ポリシーは...」（企業固有情報なし）
```

#### 4. 根拠の透明性

```
RAG ベース AI が提示：
「2024 年の失業率は 2.4% です。
（出典：日本統計局、更新日 2024 年 6 月）」

ユーザー：
・出典を確認できる
・最新性を確認できる
・ハルシネーション かどうか判断可能

従来の LLM：
出典がない場合が多い
```

## 4. RAG の構成要素

```
【ドキュメント管理】
PDFs、Webサイト、データベース
    ↓
テキスト分割（Chunking）
    ↓
埋め込みベクトル化
    ↓
【ベクトルデータベース】
Pinecone、Weaviate、Chroma など
    ↓
【検索エンジン】
質問をベクトル化 → 類似検索
    ↓
【LLM】
検索結果 + 質問を入力
    ↓
【出力】
根拠ある回答 + 出典
```

## 5. 具体例

### 例1：医療 RAG

```
医療 RAG システム：
ドキュメント：
・医学論文データベース
・厚生労働省ガイドライン
・臨床試験データ

患者質問：「頭痛に対する最新の治療法は？」

処理：
1. 「頭痛」「治療」のベクトルで検索
2. 最新の医学論文を取得
3. LLM が根拠ある回答を生成

出力：
「最新の医学的知見によると、XXX は頭痛に対して
効果的です。根拠：最新医学論文 2024 年」

利点：
・医学的根拠が明確
・ハルシネーション が減る
・患者が安心できる
```

### 例2：企業サポート RAG

```
顧客サポート RAG：
ドキュメント：
・FAQ データベース
・製品マニュアル
・トラブルシューティングガイド
・過去のサポート記録

顧客質問：「WiFi が接続できません」

処理：
1. 「WiFi」「接続」で検索
2. トラブルシューティングガイドを取得
3. LLM が具体的な解決手順を生成

出力：
「WiFi 接続できない場合、以下の手順をお試しください：
1. ルーターを再起動
2. ...
（マニュアルより）」

利点：
・一貫性のあるサポート
・対応時間短縮
・ハルシネーション による不正確な指導なし
```

### 例3：法律 RAG

```
法律 RAG：
ドキュメント：
・判例検索データベース
・法律条文
・解説記事

弁護士質問：「著作権侵害の過去判例は？」

処理：
1. 「著作権」「侵害」「判例」で検索
2. 関連判例を複数取得
3. LLM が判例分析を生成

出力：
「過去の判例では以下の事例があります：
・事例 A：...（判例 YYYY 年）
・事例 B：...（判例 YYYY 年）」

利点：
・法律的正確性
・判例に基づいた回答
・弁護士の調査効率化
```

### 例4：研究論文 RAG

```
研究論文 RAG：
ドキュメント：
・学術論文データベース
・学会発表記録

研究者質問：「量子コンピューティングの最新動向は？」

処理：
1. 最新論文を検索
2. 引用関係を分析
3. トレンドを要約

出力：
「2024 年の量子コンピューティング研究は
以下の傾向があります：
1. XXX に関する論文が増加
2. XXX の企業が投資拡大
（最新論文 10 編より）」

利点：
・最新研究トレンド把握
・信頼できる情報源
```

## 6. RAG vs 従来の LLM

| 項目 | 従来の LLM | RAG |
|------|-----------|-----|
| 知識源 | 事前学習データのみ | 事前学習 + 外部DB |
| 最新性 | 知識カットオフまで | リアルタイム可能 |
| ハルシネーション | 多い | 少ない |
| 企業知識 | 対応不可 | 対応可 |
| 出典 | なし | あり |
| 計算量 | 少ない | 多い |
| 実装複雑度 | 低い | 高い |
| コスト | 低い | 中～高い |

## 7. 試験で出やすいポイント

1. **RAG の定義**
   - 外部知識を統合した生成AI

2. **仕組み**
   - 検索 → LLM に統合 → 根拠ある回答

3. **ハルシネーション 削減**
   - 根拠となる情報を提供

4. **ベクトルデータベース**
   - セマンティック検索

5. **応用例**
   - 医療、企業サポート、法律など

---

## 8. 間違えやすいポイント

❌ **間違い1**: 「RAG = LLM の置き換え」
✅ **正解**: RAG は LLM を拡張・補強する技術

❌ **間違い2**: 「RAG = 完全にハルシネーション を排除」
✅ **正解**: 大幅に削減しますが、完全には排除不可

❌ **間違い3**: 「RAG = 常に必要」
✅ **正解**: 用途によって判断（単純な質問なら LLM のみで十分）

❌ **間違い4**: 「ベクトルデータベース = 新しい技術」
✅ **正解**: 埋め込み技術は既存、DB への応用が RAG

❌ **間違い5**: 「RAG = 無限の知識を持てる」
✅ **正解**: DB に含まれる情報のみ

## 9. 確認問題

### 問題1
RAG の定義として正しいものはどれですか？

A) 外部知識ベースを統合した生成AI
B) 説明責任を無視する
C) 社会の影響を考えない
D) 使いにくい操作を設計する

**答え**: A

**解説**: RAG は、データベースから取得した情報に基づいて LLM が回答します。

---

### 問題2
RAG が生成AIに追加する効果として正しいものはどれですか？

A) 利用者の声を無視する
B) 外部知識ベースから根拠となる情報を提供
C) 社会の影響を考えない
D) 偏りを放置する

**答え**: B

**解説**: 根拠となる情報を提供することで、推測に基づくハルシネーション が減ります。

---

### 問題3
RAG におけるベクトル検索の特徴として正しいものはどれですか？

A) 評価手順を省略する
B) 偏ったデータで学習する
C) セマンティック検索、意味的な類似性を検出
D) テストデータを学習に使う

**答え**: C

**解説**: ベクトル化により、キーワード完全一致に依存せず、意味的に類似した情報を検索できます。

---

### 問題4
最新情報に対応するための RAG の特徴として正しいものはどれですか？

A) 多様性を無視する
B) リアルタイムデータベースから情報を取得
C) データの質を無視する
D) 持続可能性を無視する

**答え**: B

**解説**: 最新のドキュメント DB に接続することで、知識カットオフを超えた情報に対応できます。

---

### 問題5
RAG の応用分野として適切なものはどれですか？

A) 効果を測定しない
B) 安心感を考えない
C) ルールより速度を優先する
D) 医療相談、法律相談、企業サポート

**答え**: D

**解説**: 正確性と根拠が重要な分野で RAG の効果が最大です。

---

### 問題6
RAG でドキュメントを扱うときの前処理として正しいものはどれですか？

A) ドキュメントを分割したテキスト単位
B) 使いやすさを考えない
C) 重要な結果を隠す
D) 対象を限定しすぎる

**答え**: A

**解説**: 大規模ドキュメントを小分けにすることで、効率的に埋め込み化・検索します。

---

### 問題7
RAG のメリット全体を表す説明として正しいものはどれですか？

A) 結論がない
B) 利用者の意見を無視する
C) RAG は外部 DB 統合、最新性、根拠透明性が向上
D) 過学習だけを避けようとする

**答え**: C

**解説**: RAG の複数の利点が従来の LLM の限界を補います。

---

### 問題8
次のうち正しいものはどれですか？

A) 説明を雑にする
B) テストデータを学習に使う
C) ユーザーが情報の信頼性と出所を確認可能
D) 使いにくい操作を設計する

**答え**: C

**解説**: 根拠となる出典を示すことで、ユーザーが情報の信頼性を判断できます。

---

### 問題9
次のうち正しいものはどれですか？

A) テストデータを使ってモデルを選ぶ
B) 社内ポリシー、製品マニュアル、FAQ、過去の記録
C) 偏りを放置する
D) 使いにくい操作を設計する

**答え**: B

**解説**: 企業固有の信頼できる情報を DB に含めることが重要です。

---

### 問題10
次のうち正しいものはどれですか？

A) いいえ、大幅削減が限界
B) ルールより速度を優先する
C) 失敗を否定する
D) 過学習だけを避けようとする

**答え**: A

**解説**: RAG でも、DB の情報が不完全な場合や検索ミスでハルシネーション は起こり得ます。

## 10. 今日のまとめ

**RAG** は、外部知識ベースを統合した生成AI です。

**仕組み**：検索 → LLM に統合 → 根拠ある回答

**利点**：ハルシネーション 削減、最新情報対応、企業知識対応、透明性向上

**応用例**：医療、法律、企業サポート、研究支援

**限界**：DB の品質に依存、検索精度が重要
