## 3. 本日の内容

### LLM とは

**定義**：大規模なテキストデータで学習した言語モデル。次の単語を予測する能力により、自然な文を生成。

（LLM: mô hình ngôn ngữ được huấn luyện trên dữ liệu văn bản lớn）

```
特徴：
・パラメーター数：数十億～数兆
・学習データ：インターネット全体などの大量テキスト
・主な技術：Transformer
・能力：テキスト生成、質問応答、翻訳など
```

### LLM の構造

```
入力テキスト
    ↓
【トークン化】
テキストを最小単位に分割
「私は猫を飼っている」
→ 「私」「は」「猫」「を」「飼」「っ」「て」「い」「る」

    ↓
【埋め込み（Embedding）】
各トークンをベクトル表現に変換
「私」→ [0.1, -0.3, 0.5, ...]

    ↓
【Transformer エンコーダー/デコーダー】
Self-Attention で文脈を理解
複数層を通過

    ↓
【出力層】
次のトークンの確率分布を計算
「は」（70%）「が」（20%）「も」（5%）...

    ↓
出力：確率的にサンプリング
```

### LLM の学習方法

**フェーズ1：事前学習（Pre-training）**

```
目的：言語の本質的なパターンを学ぶ

学習データ：
・Wikipedia
・ウェブページ
・書籍
・技術ドキュメント
・その他あらゆるテキスト

学習タスク：次の単語を予測
「太郎は昨日公園で___を食べた」
正解：「犬」（可能性もあるが）「アイスクリーム」（高確率）

パラメーター数：
- GPT-2：1.5 億
- GPT-3：1,750 億
- GPT-3.5：1,750 億（推定）
- GPT-4：より大規模（非公開）

計算時間：数ヶ月（大規模 GPU クラスター使用）
```

**フェーズ2：ファインチューニング（Fine-tuning）**

```
目的：特定タスクに最適化

方法：
1. 事前学習済みモデルをベース
2. 特定タスクの少量データで学習
3. パラメーターを微調整

例：
・通常の LLM：「次の単語を予測」
・カスタマーサポート版：顧客対応を学習
・医療版：医学用語を学習

利点：
・少量データで高性能を実現
・学習時間が短い
・計算コストが低い
```

### LLM の能力：なぜ「理解しているように見えるか」

#### 1. パターンマッチング

```
LLM は、学習データ内の統計的パターンを認識

例：「太郎は医者で、診察を___」
パターン：医者＋診察 → 「している」「行った」など

LLM の処理：
単語の共起パターン（同時に現れる確率）を計算
→ 自然な文を生成
```

#### 2. 複雑な依存関係の学習

```
Transformer の Self-Attention：
文中の遠く離れた単語同士の関連性を学ぶ

例：「去年ニューヨークに行った。その時見た___は素晴らしかった」
「その時」「ニューヨーク」の関連性を認識
→ 適切な単語（Statue of Liberty など）を予測
```

#### 3. インコンテキスト学習

```
プロンプト内の例から学習：

プロンプト：
「翻訳の例：
犬 → dog
猫 → cat
私は学生です → ？」

LLM：
1. 前の翻訳例からパターンを認識
2. 文法構造を理解
3. 「I am a student」を生成

→ 学習データに「私は学生です」がなくても対応
```

### 主要な LLM の比較

| モデル | 企業 | リリース | パラメーター | 特徴 |
|--------|------|---------|-------------|------|
| BERT | Google | 2018年 | 3.4 億 | エンコーダーのみ、双方向 |
| GPT-2 | OpenAI | 2019年 | 1.5 億 | テキスト生成、シンプル |
| GPT-3 | OpenAI | 2020年 | 1,750 億 | 高性能、Few-shot 学習 |
| PaLM | Google | 2022年 | 5,400 億 | 高性能、推論性能優秀 |
| GPT-3.5 | OpenAI | 2022年 | 1,750 億（推定） | ChatGPT ベース |
| GPT-4 | OpenAI | 2023年 | 非公開（1兆以上） | 最高性能、画像対応 |
| Llama | Meta | 2023年 | 7B～70B | オープンソース、軽量 |

## 4. 具体例

### 例1：テキスト生成

```
プロンプト：「物語を書いてください。テーマ：失われた宝石」

LLM の処理：
1. 「物語」「宝石」「失われた」のパターンを認識
2. 冒険物語の典型的なパターン（起承転結）を学習
3. 次々と自然な文を生成

出力：
「昔々、ある王国にはめったに見ない紫色の宝石がありました。
その宝石は、王妃の娘によって盗まれました...」

特徴：
・文法が正確
・物語構造を理解
・創造的に見える（実は統計的パターン）
```

### 例2：質問応答

```
プロンプト：「太陽系について説明してください」

LLM の処理：
1. 「太陽系」についての学習データを活用
2. 関連する惑星、彗星などの情報をパターンマッチング
3. 連接的で情報的な答えを生成

出力：
「太陽系は太陽を中心とした天体系です。8つの惑星（水金地火木土天海）
があり、それぞれが太陽を公転しています。地球は第 3 惑星で、
生命が存在する唯一の天体です...」

特徴：
・情報が正確（ただし常にではない）
・構造化された説明
```

### 例3：翻訳

```
プロンプト：「『こんにちは、私の名前は太郎です』を英語に翻訳してください」

LLM の処理：
1. 日本語文の構造を認識
2. 学習データから日本語←→英語のパターンを抽出
3. 適切な英文を生成

出力：
「Hello, my name is Taro.」

特徴：
・自然な英語
・文法的に正確
・ただし常に完璧ではない
```

### 例4：コード生成

```
プロンプト：「Python で 1 から 100 までの合計を計算するコードを書いてください」

LLM の処理：
1. 「Python」「合計」「100」のパターンを認識
2. 学習データからプログラミングパターンを抽出
3. 効率的で読みやすいコードを生成

出力：
def sum_to_100():
    return sum(range(1, 101))

# または

total = 0
for i in range(1, 101):
    total += i
print(total)

特徴：
・複数の実装方法を提案可能
・エラーハンドリングがないことも
```

## 5. LLM の能力と限界

### 能力

✓ 自然言語理解と生成  
✓ 文脈の理解（長いテキストでの関連性）  
✓ 複数の言語での対応  
✓ 推論（簡単な論理問題）  
✓ クリエイティブなテキスト生成  

### 限界

✗ 事実性の不確実性（ハルシネーション）  
✗ 最新情報への対応（学習データの日付まで）  
✗ 極度に複雑な数学演算  
✗ 独立した思考や意思決定  
✗ 感情の真の理解  
✗ 常識的な判断（時々）

## 7. 間違えやすいポイント

❌ **間違い1**: 「LLM = ChatGPT のみ」
✅ **正解**: BERT、GPT、PaLM、Llama など、多くの LLM がある

❌ **間違い2**: 「LLM は完全に理解している」
✅ **正解**: 統計的にパターンを予測しているに過ぎない

❌ **間違い3**: 「より大規模 = 常に優れている」
✅ **正解**: 大規模さと性能は相関があるが、一対一ではない

❌ **間違い4**: 「LLM は常に事実を述べている」
✅ **正解**: ハルシネーションで不正確な情報を生成することもある

❌ **間違い5**: 「LLM = 人間の知能を持っている」
✅ **正解**: 統計的パターンマッチング、本当の理解ではない

## 7. 確認問題

### 問題1
大規模言語モデル（LLM）の定義として正しいのはどれですか？

A) 過学習だけを避けようとする
B) 画像処理に特化したモデル
C) 小さなテキスト処理モデル
D) 大規模なテキストデータで学習した言語モデル

**答え**: D


**解説**: LLM は、インターネット全体などの大量テキストから言語パターンを学習します。

---

### 問題2
LLM の基本的な学習タスクは何ですか？

A) 結果だけを求める
B) 過学習だけを避けようとする
C) 次の単語を予測
D) 検証をせず進める

**答え**: C


**解説**: LLM は、与えられたテキストの次の単語を予測する自己教師学習により、言語パターンを学びます。

---

### 問題3
トークンとは何ですか？

A) 過去の例だけに頼る
B) テストデータを使ってモデルを選ぶ
C) テキストの最小単位（単語やサブワード）
D) 利用者の声を無視する

**答え**: C


**解説**: LLM は、テキストをトークン化して処理し、各トークンを数値ベクトルに変換します。

---

### 問題4
ファインチューニングとは何ですか？

A) 関係者を見ない
B) 事前学習済みモデルを特定タスクに最適化
C) 利用者の声を無視する
D) 偏りを放置する

**答え**: B


**解説**: ファインチューニングにより、大規模データで学習したモデルを、少量の特定データで特定タスクに適応させます。

---

### 問題5
LLM が「理解しているように見える」理由は何ですか？

A) 継続学習をしない
B) 学習とテストのデータを混在させる
C) プログラミングで知識を入れている
D) 統計的パターンを認識し、複雑な依存関係を学んでいるから

**答え**: D


**解説**: LLM は実は、大規模データから学習した統計的パターンを利用して、自然なテキストを生成しています。

---

### 問題6
GPT-2 と GPT-3 の主な違いは何ですか？

A) 今だけで満足する
B) パラメーター数が大幅に異なり（1.5 億 vs 1,750 億）、能力に大きな差
C) 対象を定めない
D) 使いにくい操作を設計する

**答え**: B


**解説**: GPT-3 は GPT-2 の約 100 倍のパラメーターを持ち、はるかに高性能です。

---

### 問題7
インコンテキスト学習とは何ですか？

A) プロンプト内の例から学習し、新しいタスクに対応する
B) 重要な結果を隠す
C) 偏った対象だけを重視する
D) テストデータを学習に使う

**答え**: A


**解説**: プロンプト内に翻訳例や問題例を示すことで、LLM はその例から学習し、同様のタスクに対応できます。

---

### 問題8
Transformer の Self-Attention で、文中の離れた単語の関連性を学べる理由は何ですか？

A) 説明を雑にする
B) 今だけで満足する
C) 表示だけを変える
D) テキスト内の遠く離れた単語同士の関連性を学べる

**答え**: D


**解説**: Self-Attention により、「その時」と「ニューヨーク」のような離れた単語の関連性を理解できます。

---

### 問題9
LLM の主な限界は何ですか？

A) ルールより速度を優先する
B) ハルシネーション、最新情報への非対応、常識的判断の困難さ
C) 説明責任を果たさない
D) 利用者の声を無視する

**答え**: B


**解説**: LLM には技術的・概念的な多くの限界があります。

---

### 問題10
LLM は本当に言語を「理解」していますか？

A) いいえ、統計的パターンマッチングであり、本当の理解ではない
B) 説明責任を果たさない
C) 更新を怠る
D) 専門用語をそのまま使う

**答え**: A


**解説**: LLM は実は、大規模データから学習した確率分布に基づいて次の単語を予測しているに過ぎません。

## 8. 今日のまとめ

**LLM** は、大規模テキストデータで学習した言語モデルです。

**次の単語予測**により、言語パターンを学習します。

**Transformer + 大規模データ** が、高性能 LLM を可能にしました。

**能力**：テキスト生成、翻訳、質問応答、コード生成など

**限界**：ハルシネーション、最新情報への非対応など
